# 原生数据订阅与历史

`ParquetDataFeed` 从 `input.json` 的 `native_data` 装载原生订阅与冻结规则。运行配置同时指定 `history-provider=QuantWitness.LeanInput.NativeHistoryProvider`。订阅、原生 `History`、预热和证券初始价格不回退默认行情文件。显式或LEAN默认的填充请求由上游 `FillForwardEnumerator` 在已可见真实流之后处理，保留 `IsFillForward`，填充行情不能用于成交。

`native_data` 保存订阅绑定与补充时钟。绑定证券与本次运行清单相同时，直接引用 `input.json` 的证券列表。现货执行窗口保存共用时刻和逐交易日例外，包含开始、结束、会话开盘和会话收盘。时钟从窗口恢复已确认的点和区间，其余事件与窗口显式保存。`native-bindings.json` 保存需要 Python 直接读取的数据来源。C# 进程共享只读的 `input.json` 与 `strategy-input.json`，每个文件解析一次。

股票和 ETF 的日线与一分钟规则直接读取冻结计划的规则 Parquet。读取器按证券和规则类型索引有效日期和版本，按执行窗口选取可见版本。相同模板组合共享已校验的结算、数量和费用字段，价格、停牌与生命周期继续按当日可见版本读取并核验。未到可见时间的版本不参与交易，跨日估费继续使用最近已可见的历史费率。C# 使用行情索引校验执行窗口的规则覆盖，包括未订阅证券。期货按冻结会话读取规则和结算；尾部只结算观察沿用独立的会话时钟。

Python 校对已准入的原始 Parquet 文件和页脚，按冻结日期与证券筛选行组。清单的 `minute_parquet` 记录选择的行组和会话。`schedules` 保存共享时段表、起止时钟模板和证券分组。每组通过一组半开行号区间选取其时段，保留上市区间、非连续交易日及证券专有时段。模板使用相对交易日的日期偏移，期货夜盘保留跨日归属。C# 流式校验入选月文件质量，先读证券列，对完全不含请求证券的批次跳过其他列。校验记录证券所在的物理行段和执行窗口内存在行情的日期；订阅、History、预热和交易按需从已校验行段读取同一份原始价格和成交量。已完成分钟在结束时点可见，History 还受请求窗口和消费时点限制。期货夜盘按冻结会话归入交易日。

成功校验后，LEAN 在当前用户的 `%LOCALAPPDATA%/QuantWitness/minute-index-v1` 下保存月索引，供后续进程复用。索引保留物理行段及覆盖统计，原始价量继续按需读取。复用要求冻结文件路径、大小、修改时间、页脚行数和行组、选择范围、证券会话及执行口径一致。侧车缺失、损坏或无法读取时从原始文件重建；原始文件与本次冻结清单不符时终止。该目录属于可删除的工作缓存。

内存缓存最多保留最近访问的两个自然月。字节额度按节点内存预算的三分之一计算，上限为 256 MiB。单月达到额度时淘汰较早使用的证券行情；History 可以按原冻结范围回载。运行目录的 `parquet-read.json` 中，`month_load_counts` 和 `source_rows_read` 记录实际校验的月份次数与扫描行数，`month_index_hits` 记录按月从侧车恢复索引的次数，`daily_selected_rows` 按分区去重汇总执行域逐日行数，`symbol_parquet_reads` 记录实际读取的证券明细批次与行数，`emitted_rows` 记录交付订阅和历史的行数。统计同时记录结束时驻留月份与记账缓存峰值。现货一分钟的 `rule_source_load_seconds` 记录规则源索引加载耗时，`rules_by_date` 记录当日实际构建规则时段数和规则校验、构建耗时。

日线、Universe 和事件绑定通过清单记录正式工件引用。引擎内的 Python 读取器使用原准入计划，只读查询 DuckDB 或读取已经存在的 Parquet 工件。日线金融检查按交易日通过整数缓冲区交给 C#。组合目标一次建立按证券访问的索引。算法可以通过 `read_fields(rows, binding_id)`、`read_field_groups(rows, binding_id)` 收取同一可见时点的字段，也可用单行 `ResearchData.Fields`。

带有效区间的来源必须公开并交付实体键、生效及失效字段，清单同时保留端点闭合规则。Feed和Universe交付已公开的区间事件，由算法按当前时点维护状态；History由既有时态选择器返回请求时点有效记录。稀疏公告或修订的变化集合不等于全市场横截面快照。排他的时间戳边界在核心微秒精度下严格晚于发布时间交付；日期公告沿冻结的下一交易日规则交付。

`NativeClockSubscription.Install` 安装独立 `ResearchClock`，空证券池仍沿冻结的 `calendar_events` 和 `calendar_windows` 推进。现货分钟在上午和下午分别发时钟，午休仅保留显式事件和执行边界。期货时钟按冻结小节走，日线沿冻结会话交付。手动证券和定时Universe使用LEAN的纯时钟订阅；数据Universe以绑定ID为证券标识，每一可见时点交付完整 `BaseDataCollection`，再由算法选择证券。

读取器强制限定研究域。交易域限制、证券金融模型及账户权益由宿主执行。已有来源缺少供应商历史修订版本时，数据接口不会补造历史版本。

现货规则打开冻结的逐日参考 Parquet 后按行组单遍读取。价格、停牌和上市状态保留整数、布尔值或字符串。行情逐日核对六类规则的有效范围，下单、成交与账户估费查询时才按证券构建完整规则。已由列式准入确认的每日涨跌停直接使用整数单位，消费时仍检查参考价可见时点、有效区间和当时规则版本。

同一活跃月份共用一个 Parquet 读句柄和列索引，移出月份缓存时关闭。读取报告里的 `partition_open_counts` 记录物理打开次数。需要隔离分钟索引时，可为 Launcher 指定 `QUANTWITNESS_MINUTE_INDEX_DIRECTORY` 目录。

同一行组的多证券读取可复用批量解码结果，行组与证券行情共享现有内存额度。读取报告记录实际的 `row_group_decodes` 次数。
