# 独立使用验收

验收对象是一份确定的完整公开源码，以及从该源码构建的 wheel。记录源码提交号；未提交的候选只能记录为工作树验收，不能登记为某个提交的验收。Linux 安装、远端 CI 和首次使用分别保存实际结果。

## 安装与 CI

按[安装与发布构建](release.md)生成候选产物，在干净环境安装本次 wheel 与所需 extras。机器学习交付使用公开源码中的验收工具：

```bash
python -I tools/verify_ml_install.py --output /path/to/new-ml-acceptance
```

输出目录必须不存在。`acceptance.json` 应记录安装位置、pip check、三个模型的训练和跨进程无标签恢复；这项检查不访问数据库。把该收据与构建回执一并保存。运行此工具的源码与安装的 wheel 须属于同一交付候选。

远端 CI 使用完整公开源码仓库的 `.github/workflows/ci.yml`，记录运行地址、源码提交、平台、任务结论以及失败日志。只有对应提交实际运行成功，才能写为远端验收通过。发布版本与执行 CI 是不同操作，CI 验收不要求发布 PyPI 包。

## 首次使用

参与者应未参与本次实现。维护者提供同一份公开源码和文档；参与者按[Workspace 入门](workspace-quickstart.md)独立完成：

1. 安装依赖并生成第一份研究报告，找到 Result 和 VerificationResult，确认独立验证状态。
2. 按入门页修改样本范围，生成第二份结果并比较数值。
3. 按入门页的失败诊断说明找到问题位置，说明应修改声明、补输入还是恢复执行。

合成环境准备会创建测试数据库，参与者先遵守本机写库授权规则。若需要维护者帮助，记录具体卡点、提供的帮助和最终结果；不把指导完成写成独立完成。自动化新环境检查单独记录，不代替参与者体验。

参与者可将下面的记录作为反馈正文，不需要提供私人数据库、账户信息或凭据：

```text
源码提交或离线交付标识：
系统与 Python 版本：
安装命令与结果：
第一份报告路径：
Result 标识与 VerificationResult 状态：
修改的参数与两次结果差异：
错误提示、定位方法与处理结果：
需要额外帮助的位置：
仍无法完成的步骤：
```

## 工件保留

交付记录保留构建回执、安装收据、CI 运行信息和参与者原始反馈。研究结果保留正式 Result 与 VerificationResult；虚拟环境、安装缓存和临时排序目录可以按使用者的保留策略清理。反馈没有返回、CI 没有运行或某项检查失败时，保持该项未完成。
