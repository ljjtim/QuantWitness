# 分钟市场规则快照

保存并选择某证券在历史时点可用的规则。

## 开始前

- 输入：完整规则、来源、有效期和可见时点。
- 输出：绑定内容身份的规则快照。
- 命令中的尖括号内容是待替换参数。

## 使用顺序

1. 声明每项规则支持状态。
2. 保留完整版本和来源。
3. 将规则身份写入分钟范围引用。
4. 准入覆盖范围。
5. 让消费者按实际时点选择版本。

分钟仿真不能拿今天的交易规则回填历史，也不能把日线表中的事后结果当成盘中已知信息。随包参考材料只覆盖平台分钟能力manifest声明的范围。A股项目可另提供完整日历和规则，并把每一条必需规则明确标为 `supported` 或 `unsupported`。

## 合同与身份

当前机器真相位于 `src/research_pipeline/domain/rule_snapshots/minute_reference_rules.v6.json`，由 `MinuteRuleSnapshotBundle` 严格读取。规则 ID 中的 `cn_fund` / `cn_futures` 是稳定外部标识，规则载荷内的资产类别统一使用 `cn_etf` / `cn_future`。bundle 固定包含：

- `capability_binding`：绑定 `domain.minute.market_rule_snapshots` 与当前平台分钟能力 manifest。
- `instruments`：标的、资产类别、交易所、可交易角色和范围元数据摘要。
- `sources`：来源类型、定位符、发布日期和声明上限。
- `rules`：规则 ID、标的、revision、有效期、可见时点、来源、参数或稳定拒绝原因。
- `bundle_hash`：规则值、有效期、可见期、来源、标的分类任一变化都会改变发布摘要。

Python新建`MinuteRuleSnapshotBundle`时可省略`bundle_hash`，构造器在完整内容校验后一次生成身份。读取JSON或列式工件必须提供原身份并核对。修改已有对象时保留的原身份也必须匹配当前内容。

列式加载在本次调用内共享重复的规则身份文本、来源元组和不可变标量参数键值对。避免年度规则把相同内容展开为数百万份对象。共享保留布尔、整数、浮点及正负零的区别。嵌套列表和对象独立加载，完整规则身份与PIT检查继续执行。

`MinuteRuleResolver`按证券、规则和有效日期取候选，排除尚不可见的修订，在同一有效区间选择已可见的最高revision。可见区间冲突、缺失、不支持或没有当时可见版本均拒绝，不使用默认值。

## 当前参考范围支持矩阵

| 标的 | 已支持 | 明确不支持 |
|---|---|---|
| `000001.XSHE` | 交易单位、已冻结 session | PIT 复权因子、生命周期可见性、逐日涨跌停、停牌、结算、券商费用 |
| `510300.XSHG` | 生命周期/股票型 ETF 类别、交易单位、T+1、逐日前收推导的 10% 价格限制、已冻结 session、显式研究成本模型 | PIT复权快照由专用工件提供。缺少历史可见停牌来源 |
| `000300.XSHG` | benchmark/non-tradable、已冻结 session | 指数成交执行不在范围内 |
| `AG2406.XSGE` | 冻结两日内的实际合约自映射、生命周期、乘数、最小变动价位、交割日、session、逐日 7% 涨跌停、成交额费率手续费、投机/套保保证金和收盘结算 | 连续合约执行、冻结窗口外规则、平今与普通平仓费率不同时的持仓日龄拆分 |

支持结论只达到 `research_observation`，不能外推为全历史、全品种或实时能力。股票分钟已按直接采集 raw 发布为 `pit_allowed`，但这只说明 completed bar 能在当前保存快照上用于历史观察。不证明精确重放供应商当年的保存版本。

ETF 只闭合 2024-01-02—05 的冻结参考窗口：成交仍使用 raw bar，复权快照只供研究特征。费用明确是研究假设，不代表真实券商账户。AG2406 也只闭合 2024-01-03—04 两个交易日，费率和保证金按各自 `available_at` 解析，结算价在 15:01 收盘事件消费。

## 来源边界

- 深交所 2023 交易规则用于参考深市股票交易单位：[官方 PDF](https://docs.static.szse.cn/www/lawrules/rule/trade/W020230217564423808793.pdf)。
- 上交所 2023 交易规则用于参考沪市 ETF 交易单位：[官方历史规则页](https://www.sse.com.cn/lawandrules/sselawsrules2025/repeal/rules/c/c_20250612_10824490.shtml)。
- 上期所白银期货合约说明用于合约单位、最小变动价位和交割规则：[官方页面](https://www.shfe.com.cn/products/futures/metal/ferrousandpreciousmetal/ag_f/standard_ag_f/202312/t20231205_327323.html)。
- 上期所 2023-09-22 长假安排明确白银恢复 7% 涨跌停、套保 8% 和投机 9%。2023-12-27 元旦安排未调整白银。公告归档与只读日线只用于核对 2024-01-03—04 的规则推导，不把日线结果倒填成盘前来源。
- session 使用仓库内已发布的分钟 session bundle。标的角色与实际合约身份来自平台分钟能力 manifest。
- ETF 生命周期、股票型类别、T+1、四个前收观测及研究费用口径记录在冻结规则bundle的来源中。它是受控本地证据，不伪称交易所正文。每日价格限制由前一交易日 15:00 已完成的前收和 10% 规则按 3 位报价精度推导。同日日线只作事后对账。

交易所链接属于 `official_citation`，不能把定位符摘要冒充网页正文。AG2406 费率和保证金另外绑定只读源记录的实际可见时间。同日 16:00 后出现的记录不能倒填此前盘中订单。冻结窗口外仍无规则默认值。

## 下游使用

规则内容身份通过`minute_scope`与`rule_bundle_hash`进入冻结节点参数和恢复身份。实际消费者按声明选择对应历史规则，缺少必要规则时拒绝执行。不能用硬编码默认值绕开resolver。Result通过持久输入与计划引用保留来源关系。

## 夜盘交易日与持仓量对账

`SessionAssignmentPolicy` 保存规则可见时间、有效区间和 `Asia/Shanghai` 时区。
普通时点使用 `[start,end)`，完成分钟使用 `(start,end]`。
交易日归属继续消费 `SessionPolicyRevision` 和 `TradingSession`。
夜盘按冻结会话归属交易日，不能直接使用自然日。

分钟完整性按每个预期结束时点核对，不能只比较总根数。成交量和成交金额对账保留分钟值、日线值、精确差值及零容差。持仓量默认使用 `strict` 政策，差异会阻断验收。

只有显式选择 `diagnostic`，差异才记录为 `open_interest_mismatch`。此时回执使用 `pass_with_diagnostic`，保留精确差值。

回溯整理的规则不能证明历史时点已经可见。
当前供应商查询也不能补造历史发布时间。
缺少历史可见性证明时，限制为 `research_observation`。
这类材料不能据此获得正式夜盘交易准入。


## 常用名称

| 名称 | 含义 |
| --- | --- |
| ResearchPackage | 数据、算法、样本、指标和预算的完整声明 |
| Catalog Lock | 已确认的字段、来源和可见性说明 |
| PIT（按时点可见） | 过去某时刻只使用当时已知的信息 |
| bar（周期行情） | 一个日线或分钟区间的行情记录 |
| OHLCV（开高低收量） | 开盘价、最高价、最低价、收盘价和成交量 |
| Feature（特征） | 决策时已知的研究输入 |
| Label（标签） | 用于评价预测的未来目标 |
| bundle（封存包） | 完整代码、依赖或数据声明及其内容身份 |
| checkpoint（检查点） | 通过验收的节点输出和恢复依据 |
| Result（正式结果包） | 正式表、运行摘要及配置、实现和输入引用 |
| minute_scope（分钟范围引用） | 指向同一冻结日历和历史规则的小引用 |
| Supervisor | 监督运行和提交结果的主进程 |
| Worker | 执行节点计算的独立进程 |
