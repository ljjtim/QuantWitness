# 中国期货LEAN执行

运行人民币期货策略并保留双向账户事实。

## 开始前

- 输入：真实合约、历史日历、规则、行情和结算。
- 输出：成交腿、四桶持仓、资金、风险和换月记录。
- 命令中的尖括号内容是待替换参数。

## 使用顺序

1. 从公开期货合成示例开始。
2. 声明合约、会话、规则与结算来源。
3. 声明显式开平手数和风险政策。
4. 准入并执行研究。
5. 按期货结果文档解释账户与收益。

人民币商品期货和金融期货使用当前ResearchPackage → 准备与准入 → LEAN → Result主链，频率为日线或一分钟。一个运行对应一个人民币期货账户，多合约共享资金。期货与现货分账。公开起点见[双向期货合成示例](../examples/lean_futures/README.md)，结果字段见[期货结果合同](lean-futures-results.md)。

## 输入与可见时间

策略声明使用`research-strategy-protocol-v4`、`asset_class=cn_future`，证券使用真实合约代码、人民币和`contract_kind=future`。历史日历及规则通过包内`minute_scope`冻结。合约必须有明确品种代码、交易所、上市与最后交易日、主动退出截止、乘数、价格尺度和tick。不以连续代码作为成交证券。

每个合约按自己的完整会话解析`trading_date`。夜盘、午夜、午休和节假日前后的会话均由冻结日历确定，不能把自然日当作交易日。行情按交易日交接，跨自然日读取相邻必要分区。会话与规则预读不改变策略可见时间。

会话所属交易日必须位于上市日至最后交易日的闭区间内。上市日的前一自然日夜盘按所属交易日判断。不同合约可以有不同的会话日期集合。日线与独立结算只读取当天实际有会话或结算事实的合约。

日线绑定`bars_request_id`与`open_request_id`，完整OHLCV按下一会话开盘可见，执行只使用独立Open。一分钟仅使用后续完成bar。期货不绑定现货公司行动snapshot。

结算可使用冻结规则中的逐日事实，或通过`settlement_request_id`读取正式列式输入。一分钟的独立结算来源使用`futures: data.columnar-bundle.v1`端口，日线与行情共用bars列式来源。

结算价保留所属交易日和实际可见时间。供应商记录缺少逐条发布时间时，采用当前研究可见性假设。假设为`next_session_open_after_1700`：在该交易日17:00之后的下一实际会话开盘消费。

AG常规会话为当晚21:00，IF为下一交易日09:30。节假日由日历决定。末日延长只结算观察时钟，不开放新交易。

该口径是明确的研究可见性假设，来源声明须保留。

保证金、手续费、涨跌停及平仓桶顺序同时按生效区间与可见时间选版。费用分别声明开仓、平仓、平今的每手分金额和名义金额ppm。NULL不能自动视为零费用。

结算派生的参考价与涨跌停不能早于依赖结算的可见时间。规则缺项、错期或尚不可见时拒绝该合约窗口。

输入准备通过规则解析器的合约、规则类型及生效日索引收集盘中变更点，保留日内可见版本。会话与结算交付键在运行内一次按日建立索引。每日只读取对应分组。

结算交付区间从当天账户最早会话起点开始，到下一交易日最早会话起点结束，左闭右开。末日保留未来只结算尾段，各合约实际结算可见时间保持不变。

## 持仓与账户

原生LEAN Future和CashBook保存唯一生产状态，C#规则插件管理long/short × today/yesterday四桶。近月净仓为零仍可同时有多空持仓、浮盈亏和保证金。数量以手计，名义金额为手数×价格×合约乘数。

| 字段 | 口径 |
| --- | --- |
| cash | 已结算余额，包含费用、平仓盈亏和已发布逐日结算 |
| unrealized_pnl | 各方向与今昨桶相对结算基价的未结算盈亏 |
| equity | cash + unrealized_pnl |
| margin | 各合约、多空方向分别累计的持仓保证金 |
| frozen_funds | 活动开仓订单冻结的保证金和费用 |
| available_funds | equity − margin − frozen_funds |

正负浮盈均进入本研究购买力。不提供锁仓或跨合约组合保证金优惠。价格保持合约精度，现金转换按人民币分处理。

正式结算将浮盈亏划入现金并更新基价，随后平仓只确认新基价之后的盈亏。今昨迁移发生在交易日边界，午夜不迁移。

## 委托与风险

期货仅接受显式手数和撤单意图，支持`market/limit`与`DAY/IOC`。买开增加多仓，卖开增加空仓。卖平减少多仓，买平减少空仓。

`position_effect`为`open`、`close`、`close_today`或`close_yesterday`。普通close按冻结的`close_priority`拆腿，每腿使用对应费用。超平拒绝，反手需要明确的平仓和开仓。

提交时冻结开仓资金或可平桶。部分成交仅消费实际份额，撤销、拒绝和过期释放剩余预占。市价开仓按当时可见涨停价估计最大冻结资金。多合约按固定事件顺序竞争共享余额。

`funds_policy=reject`在开仓资金不足时拒单。`resize`将开仓缩为能够覆盖保证金与费用的最大整数手，结果同时记录请求和提交手数。市价单的`protection_price`按合约tick验证。买入成交不高于保护价，卖出成交不低于保护价，未满足时保留真实未成交状态并遵守DAY/IOC期限。

一分钟成交使用后续完成bar的Close加声明滑点，并满足tick、涨跌停、限价及参与率。同合约订单共享当根容量。限价不满足候选价则不成交。

日线使用下一合格会话的独立Open，采用明确的无即时容量约束研究假设，不读取当天H/L/C/V。IOC在首次合格机会后取消余量，DAY在所属交易日结束过期。

可用资金为负时取消策略活动订单、等待释放并暂停策略交易。风险减仓按每手释放保证金降序、合约、方向和昨仓优先执行，数量计入平仓费用。风险订单通过真实后续合格行情成交。

无量或涨跌停不伪造成交。日线开盘前已可见结算和规则可以触发随后开盘的风险订单，开盘后触发的订单等下一次开盘。风险状态跨DAY过期保留，缺口解除并撤销剩余风险单后才在后续决策恢复策略。

风险减仓使用当前可见行情判断成交机会。如果已有风险单受阻，系统检查其他持仓是否可减。阻挡原因包括涨跌停和零容量。若其他持仓可减，系统先撤销受阻单。等待剩余平仓预占释放后，系统按固定顺序提交下一项。部分成交后按实际剩余风险缺口计算数量，不把未成交平仓量视为已释放保证金。

日线尚无当前开盘行情时，已知结算或规则仍可触发待执行风险单。尚无行情不视为零容量。实际成交继续遵守开盘前后资格和DAY过期规则。

## 换月与到期

可选`roll_plans`保存`plan_id`、`old_instrument_id`、`new_instrument_id`、`direction`、正整数`quantity`、`available_at`、`start_at`、`end_at`。同规格合约按1:1手数迁移，计划仅在可见且进入窗口后执行。开始退出后取消旧合约增仓，旧合约只减仓。

新腿可下数量为`max(0, 实际累计平旧 − 实际累计开新 − 活动新腿未成交预占)`，并受总手数和共享资金限制。旧腿部分成交、资金不足或无量允许留下真实敞口偏离。动态主力选择应使用此前已完成行情形成当时可见映射。不能默认当天供应商主力在开盘前已知。

主动退出截止是明确研究参数，与交易所或经纪商强平时刻区分。截止前通过合格行情平仓。截止仍有仓则失败。末尾要求订单终结、必要结算齐全、权益和可用资金非负、风险缺口解除，才可发布成功Result。

## 结果与恢复

`research.lean-simulation.v2`保存八张执行表和metrics。fills按成交腿记录金额，account_events保存转换后余额，lifecycle记录预占、结算、风险和换月原因。不把净仓TradeBuilder统计当作双向成交统计。

收益按权益计算，末日结算计入所属交易日的研究收益。同时保留实际valuation_at，不回填历史盘中可用资金。

输入、实现、规则、安装与配置随计划冻结。成功节点依据当前checkpoint合同复用。失败LEAN节点整体重跑。

当前运行不读取旧版本计划、checkpoint或Result作为本次执行来源。直接数据库只读，归档分支不连接数据库，迁移时携带真实输入依赖。

## 已知限制

支持范围由本次已准入合约、日期、会话和规则共同决定，不代表全市场全历史覆盖。真实行情加显式保证金或费用假设只能形成相应研究观察，不能宣称完整历史交易规则复原。不模拟实物交割、期权、实盘、Tick或盘口队列、多币种及组合保证金优惠。初始账户为空仓，跨日持仓由运行真实产生。


## 常用名称

| 名称 | 含义 |
| --- | --- |
| ResearchPackage | 数据、算法、样本、指标和预算的完整声明 |
| Catalog Lock | 已确认的字段、来源和可见性说明 |
| PIT（按时点可见） | 过去某时刻只使用当时已知的信息 |
| bar（周期行情） | 一个日线或分钟区间的行情记录 |
| OHLCV（开高低收量） | 开盘价、最高价、最低价、收盘价和成交量 |
| Feature（特征） | 决策时已知的研究输入 |
| Label（标签） | 用于评价预测的未来目标 |
| bundle（封存包） | 完整代码、依赖或数据声明及其内容身份 |
| checkpoint（检查点） | 通过验收的节点输出和恢复依据 |
| Result（正式结果包） | 正式表、运行摘要及配置、实现和输入引用 |
| minute_scope（分钟范围引用） | 指向同一冻结日历和历史规则的小引用 |
| Supervisor | 监督运行和提交结果的主进程 |
| Worker | 执行节点计算的独立进程 |
