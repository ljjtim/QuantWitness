# Parquet 快照布局

了解保存输入时怎样组织 Parquet 文件。

## 开始前

- 输入：包含 `snapshot_layout` 的当前准入计划。
- 输出：文件清单、月份分区和绑定布局策略的物理快照。
- 命令中的尖括号内容是待替换参数。

## 使用顺序

1. 在准入阶段冻结布局策略。
2. 通过正式输入保存入口生成快照。
3. 按消费者的排序合同读取批次。
4. 使用原计划、实现和文件身份。

布局策略 `adaptive-bounded-v1` 将输入 batch、文件和行组三者分开。输入 batch 控制取数工作集。布局控制文件数量和有界缓冲。`row_group_size` 控制文件内行组。

## 默认策略

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| `small_table_max_rows` | 65,536 | 小表累计行数上限 |
| `max_buffer_bytes` | 8 MiB | 待写 Arrow 数据的字节上限 |
| `row_group_size` | 65,536 | 单次行组累计行数上限 |
| `target_file_rows` | 262,144 | 单文件累计行数上限 |
| `target_file_bytes` | 32 MiB | 单文件累计未压缩 Arrow 数据上限 |
| `compression` | `zstd` | Parquet 压缩 |

小表同时满足行数和字节上限时，输出 `small/part-000000000000.parquet`。超过任意上限后，普通大表按 `row_group_size` 与 `max_buffer_bytes` 累积有界块，并按 `year=YYYY/month=MM` 分区。日期升序领先的请求直接写出。

证券等其他主键领先、月份会反复出现的请求。先把有界 Arrow IPC 块追加到临时月份文件，再逐月编码 Parquet。同月内保持来源输入顺序，文件数由各月总行数和字节上限决定，不随输入块数增长。

最多同时打开一个 Parquet writer，不为所有月份同时保留编码器或内存缓冲。月份暂存使用系统临时目录，支持通过 `TEMP`、`TMP` 设置位置。暂存容量约为投影 Arrow 数据及 IPC 元数据大小。需要计入调用方的临时目录磁盘预算，完成及异常退出时清理。

文件字节上限度量未压缩 Arrow 数据，不能据此推断压缩文件长度。当前 writer 版本为 `pyarrow-parquet-v3`。

空表仍受 `result_cardinality` 约束。允许空结果时发布保留 schema 的单个空文件。默认拒绝。单行 Arrow 数据超过缓冲字节上限时直接拒绝，不临时放宽上限。

## 扫描顺序与时态事实

带时区时间戳按来源本地日期检查范围并划分月份，支持地区时区和固定偏移，例如 `+08:00`。月份计算不改变原列的时区、瞬时值和行顺序。

普通快照保持原月份布局的扫描顺序：先按年月排列，同月内保留来源输入顺序。小表在有界缓冲内合并月份，跨输入 batch 的划分不改变该顺序。对日期领先的主键，该顺序与准入主键顺序一致。

证券领先的主键可能跨多个月份，月份扫描顺序不等于完整 QueryIR 排序。`ArtifactResolver.iter_batches` 提供分片扫描、投影与过滤，不承诺 QueryIR 的全局排序。使用 `ParquetColumnarProvider` 重读物化结果时，SQL 显式按 `plan.query.sort` 排序。

归档物化也会在已有预算内按主键排序。其他消费者需要全局顺序时应使用其既有的明确排序合同，不能推断目录扫描已经有序。

`temporal_source` 始终写入连续编号的 `primary-key-stream`，不按月份重排，不选择或合并版本。隐藏的可见时间、修订字段及所有版本保留。`iter_batches_at` 仍在真实消费者时点做可见性与版本选择。

## 冻结与恢复身份

`AdmittedQueryPlan` v6 的 `snapshot_layout` 保存完整策略，包括策略 ID、writer 版本、压缩、分区语义、行组和所有行数/字节门槛。它进入 plan hash。逻辑快照绑定 plan hash。

物理 manifest 再绑定实际文件及同一策略。`snapshots` 与 `snapshot_layout` 同时进入数据物化算子及 Runtime adapter 的显式源码闭包，布局实现变化会改变 checkpoint 实现身份。直接传入与计划不一致的策略会在创建 staging 前拒绝。

当前物化要求计划包含冻结的 `snapshot_layout`，不能由调用方临时替换布局。缺少布局声明的计划须重新准入后使用。恢复仍核对当前计划、实现与正式工件身份。

旧 writer 版本的计划需要重新准入。已保存结果和输入文件不改写。

## 内存边界与取舍

待写缓冲既限制行数，也限制 Arrow 字节，并复制输入 slice，避免仅保留少量行却间接持有整个来源 batch。待写 RecordBatch 片段累计至 64 个时在同一缓冲内合并，限制极小输入 batch 引起的元数据对象堆积。`combine_chunks`、月份重排和小表切换到大表时存在有界副本共存，不能把 `pending.nbytes` 当作进程峰值。

provider 分配在输出 batch 之外预留三份 `max_buffer_bytes`，默认 24 MiB，用于布局复制、合并和交接工作集。普通大表不同时积压下一块。月份归并也只读取一个有界IPC块。

块数据、月份 take 副本和 writer 输入最多三份数据共存。块合并期间的输入片段与合并结果也在该预留内。当前输入 batch、Parquet 编码工作区、Python 日期和索引对象、schema、文件元数据及解释器仍由 provider 与进程余量覆盖。实际进程树资源治理继续生效。

该预留不等于精确 RSS 上限，也不自动扩大已批准资源。

小表单行组减少文件打开和元数据工作，同时会扩大单月过滤的候选解码行数。这项取舍受小表门槛限制。大表保留月份分区与统计量裁剪。

性能比较必须同时列出全量读取、日期筛选、发布耗时及缓冲/进程内存。局部吞吐不能代表完整研究链耗时。


## 常用名称

| 名称 | 含义 |
| --- | --- |
| ResearchPackage | 数据、算法、样本、指标和资源的完整研究声明 |
| Catalog Lock | 已确认的数据字段、来源和可见性说明 |
| PIT（按时点可见） | 在过去某时刻只使用当时已知的信息 |
| QueryIR | 限定字段、范围、排序和预算的数据请求 |
| DAG（计算步骤图） | 节点之间的先后依赖 |
| Artifact（工件） | 带类型、内容身份和来源引用的产物 |
| checkpoint（检查点） | 通过正式验收的节点输出及恢复依据 |
| Result（正式结果包） | 正式表、运行摘要和配置、实现、输入引用 |
| holdout（最终留出集） | 开发选择之外的最终评价区间 |
| Supervisor | 监督执行、发布检查点和记录事件的主进程 |
| Worker | 执行节点计算的独立进程 |
| manifest（清单） | 记录文件、类型、范围和内容身份的文件 |
| schema（结构） | 表的字段名称、类型和约束 |
