# 分钟规则：哪些历史事实可以使用

判断历史交易规则是否有足够来源。

## 开始前

- 输入：证券、日期、规则正文或明确来源引用。
- 输出：有界规则及其来源、可见时间和结论限制。
- 命令中的尖括号内容是待替换参数。

## 使用顺序

1. 确定本次证券和日期范围。
2. 收集当时可见的规则来源。
3. 声明规则有效期和可见时间。
4. 准入完整覆盖。
5. 保留实际来源和限制。

交易时间、涨跌停、停牌和费用规则可能随证券和日期变化。随包提供的参考规则只有明确覆盖范围。用自己的标的和历史区间时，需要提供对应时点可用的规则来源。

缺少规则依据时，应保留“不支持”或“只能观察”的结论，而不是用今天的规则自动填进过去。

## 处理规则

QuantWitness 随包提供的分钟规则 bundle 是一个窄范围参考快照。用来验证时间可见性、规则解析和仿真拒绝路径。它不是全市场规则库，也不表示框架能够直接覆盖任意标的、日期或实盘账户。

## AG2406参考来源

`AG2406.XSGE` 参考范围只覆盖 2024-01-03 至 2024-01-04。合约单位、最小变动价位和交割规则来自随 bundle 列出的上期所公开资料。费率、保证金、结算价和实际合约映射来自冻结时已经完成的本地只读观察。

原始供应商数据不随框架分发，因此这些值的声明上限保持为 `research_observation`。不能外推到其他日期、其他合约或历史实盘决策。

规则的 `available_at` 是框架用于拒绝前视读取的可见性边界。冻结窗口之外没有默认值。缺失、重叠或晚于决定时点的规则必须失败。

## ETF参考来源

`510300.XSHG` 参考范围只覆盖 2024-01-02 至 2024-01-05。交易单位参考随 bundle 列出的上交所公开规则。ETF 类别、生命周期、T+1、前收观察和研究费用口径来自冻结时完成的本地只读观察。原始供应商数据不随框架分发，研究费用也不代表任何真实券商账户。

价格限制由前一交易日已经完成的前收观察和 bundle 中声明的规则推导。同日日线只用于事后核对，禁止成为盘中或盘前输入。PIT 复权仍由研究自己的显式快照负责，不能从这个参考 bundle 推断。

## 分发边界

公开仓库只分发规则合同、窄范围参考值、官方定位符和本页的限制说明。不分发市场数据库、供应商导出或内部任务记录。扩展资产或日期需要先扩展平台准入能力，再发布可追溯规则 bundle。

并把来源、有效期、可见时点和声明上限一起冻结。随包参考覆盖按已发布标的与窗口核对。A股项目使用包内`minute_scope`提供完整日历和规则，并以`rule_bundle_hash`绑定内容。

编译检查实际请求覆盖、来源与能力绑定，运行按消费时点选择可见版本。参考期货数据本身不足以完成策略准入。完整策略须满足[期货执行合同](lean-futures.md)。

## 当前完整现货合同

随包股票与ETF默认规则仍保留缺少历史盘前交易状态的unsupported项。LEAN执行要求冻结数量、价格限制、生命周期、停牌、结算及费用事实。不能仅凭下一根行情存在补造盘前状态。规则、PIT与执行关系见[一分钟策略](minute_simulation.md)。

## 公司行动来源与封存

股票和 ETF 的基础权益使用完整 `CorporateAction` v2。公告、修订、生效、登记、现金到账、股份到账及可卖事实分别保留来源和时间。股票现金派息、红股到账和转增到账分别取 `a_bonus_date`、`dividend_arrival_date`、`a_transfer_arrival_date` 对应事实。研究价格的复权快照不能替代实际现金与股份权益。

公司行动由正式PIT快照交给LEAN，保留完整来源和可见时间。当前执行支持毛额现金分红和整数送转，按登记持仓、付款、股份到账和可卖时点处理。股票和ETF分别使用2、3位价格精度，现金以分记账，见[账户与权益](spot_account.md)。

## 项目A股范围

A股可以通过[项目日历与规则v2](minute-project-scope.md)覆盖参考样本之外的证券和日期。完整日历、规则版本及来源身份随计划冻结。前收盘价与涨跌停按交易日声明，制度规则按有效区间声明。未提供项目材料时继续执行随包参考制品的原有范围。

## 股票公司行动与上市首日

股票`finance.STK_XR_XD`采用供应商当前保存的历史事件，实施公告后首个真实交易日09:15可见。`addTime/modTime`仅为维护信息，不要求供应商没有提供的历史版本。请求包含`note`，明确不向原股东分配的转增不产生原持仓转增权益。

非零现金、红股或转增仍要求真实到账和可卖日期。ETF继续使用其版本可见性合同。

上市首日没有前一已完成日因子时，`data.minute.adjustment_snapshot`可声明`initial_listing_evidence`，包含`instrument_id`、`listed_date`、`available_at`与`source_reference`。仅支持股票，上市日等于适用起点的上海日期，证据须不晚于适用起点及当日09:30。上市前公告可直接作为来源。

以当日有效开盘行情作为证据时，可见时点为09:30。初始因子1只是归一化原点。已有前日因子、上市前或当日已有生效公司行动时，不采用该原点。

多股票使用`initial_listing_evidence_by_instrument`，按证券分别核对。


## 常用名称

| 名称 | 含义 |
| --- | --- |
| ResearchPackage | 数据、算法、样本、指标和预算的完整声明 |
| Catalog Lock | 已确认的字段、来源和可见性说明 |
| PIT（按时点可见） | 过去某时刻只使用当时已知的信息 |
| bar（周期行情） | 一个日线或分钟区间的行情记录 |
| OHLCV（开高低收量） | 开盘价、最高价、最低价、收盘价和成交量 |
| Feature（特征） | 决策时已知的研究输入 |
| Label（标签） | 用于评价预测的未来目标 |
| bundle（封存包） | 完整代码、依赖或数据声明及其内容身份 |
| checkpoint（检查点） | 通过验收的节点输出和恢复依据 |
| Result（正式结果包） | 正式表、运行摘要及配置、实现和输入引用 |
| minute_scope（分钟范围引用） | 指向同一冻结日历和历史规则的小引用 |
| Supervisor | 监督运行和提交结果的主进程 |
| Worker | 执行节点计算的独立进程 |
