# 一分钟策略的规则绑定与执行

用已完成的一分钟行情执行策略。

## 开始前

- 输入：已准入分钟输入、市场规则和 LEAN 安装。
- 输出：正式执行表、账户终态及指标。
- 命令中的尖括号内容是待替换参数。

## 使用顺序

1. 按 LEAN 文档准备完整安装。
2. 声明一分钟执行模型及输入。
3. 准入研究包。
4. 执行并检查正式 Result。
5. 失败时按节点恢复规则处理。

股票和ETF一分钟策略通过ResearchPackage准入后，由本地LEAN执行。节点声明`execution_backend=lean`、`execution_model=lean_next_completed_close_v1`及冻结安装身份，正式输出为`research.lean-simulation.v2`。安装、输入与运行步骤见[LEAN执行](lean-execution.md)，回调及委托接口见[策略事件协议](strategy-protocol.md)。

## 行情与规则

行情只接受原始未复权、已完成且质量合格的一分钟记录。`interval_minutes=1`，策略决策只能使用当时已经可见的行情和信号。委托按后续完成分钟Close加声明滑点成交。

日历及市场规则通过包内`minute_scope`冻结。规则按证券、业务日期和实际使用时点选择可见版本。缺少必需规则、不支持或版本冲突时拒绝执行。

数量格点、价格限制、停牌、T+1、费用和资金约束在实际执行处检查。规则结构见[分钟市场规则快照](minute_market_rules.md)，来源和公司行动见[分钟规则来源](minute_rule_provenance.md)。自有证券与日期范围见[项目分钟范围](minute-project-scope.md)。

公司行动区分公告可见、登记、生效、现金到账、股份到账及可卖日期。毛额现金红利按登记持仓确认，到账后进入现金。整数送转股份按到账和可卖时点处理。研究价格的复权快照不能代替真实现金与股份权益。

## 结果与恢复

Result保存`lean/orders`、`lean/intents`、`lean/daily`、`lean/trace`和`lean/metrics`，以及账户终态、策略状态、安装锁、策略输入和引擎摘要。行情、规则、公司行动和信号保留持久工件与计划引用，归档时同时保留实际依赖。

成功节点只有在输入、实现、配置和正式工件一致时才能复用checkpoint。未完成LEAN节点整体重跑。已发布Result只读，报告失败不重新交易。当前执行范围和限制以[LEAN执行](lean-execution.md)为准。


## 常用名称

| 名称 | 含义 |
| --- | --- |
| ResearchPackage | 数据、算法、样本、指标和预算的完整声明 |
| Catalog Lock | 已确认的字段、来源和可见性说明 |
| PIT（按时点可见） | 过去某时刻只使用当时已知的信息 |
| bar（周期行情） | 一个日线或分钟区间的行情记录 |
| OHLCV（开高低收量） | 开盘价、最高价、最低价、收盘价和成交量 |
| Feature（特征） | 决策时已知的研究输入 |
| Label（标签） | 用于评价预测的未来目标 |
| bundle（封存包） | 完整代码、依赖或数据声明及其内容身份 |
| checkpoint（检查点） | 通过验收的节点输出和恢复依据 |
| Result（正式结果包） | 正式表、运行摘要及配置、实现和输入引用 |
| minute_scope（分钟范围引用） | 指向同一冻结日历和历史规则的小引用 |
| Supervisor | 监督运行和提交结果的主进程 |
| Worker | 执行节点计算的独立进程 |
