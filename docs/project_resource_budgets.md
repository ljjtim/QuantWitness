# 为研究分配内存、时间和进程

## 开始前

- 区分单节点预算与整次运行容量。
- 按实际进程树预留 Supervisor 和 Worker 开销。
- 为输入、模型、临时文件和输出保留空间。
- 修改预算后重新准入研究包。

Supervisor 负责监督执行。Worker 负责节点计算。驻留内存（RSS）是进程当前占用的物理内存。

计算步骤图（DAG）规定节点依赖。检查点（checkpoint）保存通过验收的节点输出。

## 设置流程

1. 查看算子默认资源声明。
2. 在节点的 `resource_profile` 中覆盖必要维度。
3. 准入研究包并读取 `node_resources`。
4. 显式设置足以容纳节点的运行容量。
5. 执行研究并检查实际资源回执。

节点预算不会自动提高运行容量。
`--workers` 也不会增加总容量。
正式结果包（Result）保留实际运行记录。

你可以给研究计算设置资源上限，避免一次实验拖垮整台机器。预算决定允许用多少资源，不改变研究的数据时点和金融含义。下面解释默认额度、进程计数及超限后的行为。

## 处理规则

系统按每条父子边的实际创建时间核对进程归属。Windows 可能复用已退出父进程的 PID。时间核对防止系统把旧进程链计入当前节点。已经观测到且身份未变的存活后代，即使父进程先退出仍计入资源和清理范围。复用为非子孙的PID不再属于该节点。

进程槽超限回执在`exceeded.process_slots`中返回`actual`与`limit`，用于区分真实子进程容量不足和其他资源超限。

内建节点的低内存默认档为 1 GiB（1,073,741,824 字节）。这个档位用于已登记的低内存节点，例如 Catalog 准入和分钟观察。其他物化、模型与仿真的 2／4／8 GiB 预算保留。日频模型 split 与 locked holdout 声明 16 GiB。

该默认值来自 OperatorDefinition 的资源声明，编译进入节点计划。它不覆盖项目显式声明的小额度，也不自动提高运行总容量。CPU、临时磁盘、进程槽与超限拒绝规则各自保持。

预算声明变化要求重新准入，旧冻结计划不静默改写。

## 日频模型输入与序列预算

`research.model.selection`默认4 GiB，与predict一致。选择节点冻结 validation 结果后，还要恢复模型并执行 test 推理。预算覆盖 Torch/CUDA 解释器基线、当年完整候选窗口和处理器副本。它不是只读取指标表的节点。运行总容量仍由调用声明决定，节点默认值变化不会提高总容量。

日频模型split与locked holdout的默认内存为16 GiB。Feature逐批完成源记录校验后按有界证券分组转换为宽上下文，不把全历史特征长表常驻内存。标量Feature与显式向量Feature共用时间、重复键及来源规则。

向量的列名固定在value字段的model_feature_value_names元数据中，逐分片核对名称及顺序。缺少或冲突的元数据拒绝，不猜测特征维数。

序列成员仅保存sample_id、step和context_index，窗口构建与绑定按有界数组核对日历、证券、可见日期和特征值。标签缺失不删除当时股票池中的预测节点。训练和评价只消费合格的已成熟标签。预算覆盖共享上下文、绑定副本和Qlib实际日期×证券矩阵，不重复累计已保留的同一工作集。

每日横截面模型还计入股票对的注意力中间张量。不能只按单股票循环网络估计。CUDA候选使用冻结设备，当前只允许串行执行，模型配置记录实际设备及allocated/reserved显存峰值。

GPU不可用时停止，不静默切换CPU。资源声明不是实测峰值。正式运行继续采样驻留内存并执行既有超限规则。

项目 Worker 的节点租约覆盖当前 Supervisor、当前 Worker 及其后代，RSS 与进程槽使用同一范围。默认串行调度每次节点租约只计一次Supervisor。显式并行把共享Supervisor与各节点专属进程树分别计入总包络，不按CPU槽或进程槽倍乘父进程开销。

其他运行的进程不进入当前 Worker 树。Worker 正常退出、测量异常或用户中断均进入进程清理。正常退出后仍检查内存、临时空间、进程槽和时间。

节点外层采样覆盖 COMMITTED、目录发布与内容复验。写入成功事件前，系统按节点预算与租约的最小上限核对峰值。超额或测量不可用进入失败状态。

Windows Python 3.10 的环境身份采集可能通过 `cmd.exe /c ver` 查询系统版本，该短命进程同样占用 Worker 的进程槽。公开合成示例显式声明 4 槽，覆盖 Supervisor、venv 启动器、实际 Worker 和系统版本查询。未增加 CPU 并行度，也不改变核心默认预算。项目自行启动其他进程时仍须按实际树声明额度。

项目 Worker 的内存或临时空间超额保持 `project_worker_resource_exceeded` 错误码。CLI JSON 的 `data.exceeded` 按 `memory_bytes`、`temp_bytes` 返回各超额维度的 `actual` 与 `limit`，单位为字节。同时超额时保留两项。资源测量状态和进程清理状态继续独立返回。

## 运行容量与启动开销

ResourceBudget 与进程测量、清理工具由 platform 提供。Runtime 按冻结节点预算和运行总容量申请资源。普通 Workspace execute 在准备与准入时汇总实际节点声明，提示项目 Worker 的已知启动开销。

进程内核心节点不套用 Worker 槽位建议。建议不自动加额度。

项目 Worker 与 LEAN 宿主的父进程及后代计入同一预算。Windows 虚拟环境启动器同样计数。实际超限返回 actual、limit、测量状态和清理状态。进程退出后仍完成末端资源核对，清理不完整禁止发布成功。

运行容量使用 --resource-memory-bytes、--resource-cpu-slots、--resource-scratch-bytes。共享池额外声明总进程槽。--workers 不增加总预算。run --no-node-timeout 仅取消主 DAG 节点累计时长上限，资源租约等待和单次策略回调限时继续生效。

`run --no-temp-limit`取消本次运行的临时磁盘额度，节点有效预算和运行容量的`temp_bytes`记录为JSON `null`。`0`仍表示零额度。该选择随invocation冻结，恢复使用原选择。

内存、CPU、进程和时间约束继续生效。磁盘用量和交接期间的峰值照常采样，成功分区的已交接工作副本照常释放，正式工件保留。

共享资源池的容量是固定身份。不限临时空间的运行使用容量相符的资源池目录，不能把已有有限额度的池静默改为不限。有限容量也不能接受不限空间的请求。不限额度不增加实际磁盘容量，文件系统空间耗尽仍会导致写入失败。

## 冻结预算与容量错误

`package admit` 的 `node_resources` 返回每个冻结节点的 `node_id` 和 `resource_budget`，包含内存字节、CPU 槽、临时空间字节及时间上限。Workspace 准备后的资源展示也读取冻结 DAG。独立 lint 展示算子声明。两者都不把声明上限当作实测用量。

单节点声明超出运行总容量时，CLI 返回 `runtime_resource_admission`。`data.node_id` 标明节点。`data.exceeded` 按维度返回 `requested` 和 `capacity`，一次保留全部超限项。例如内存请求 8 GiB、容量 4 GiB 时，`memory_bytes` 中分别为 8589934592 和 4294967296。操作者据此选择修改研究声明并重新准入，或显式调整运行容量。

框架不自动提高额度。串行与并行调度使用同一单节点容量验收。

## 已知边界

资源治理依赖进程采样，不能把未观察到的短时峰值宣称为操作系统硬上限。节点声明、输入体积和实测进程峰值分别记录。没有可靠规模事实时保持 unknown。

进程与RSS沿用节点采样周期，同一监督范围在周期内复用最近真实读数。磁盘目录最多每秒遍历一次。因果子任务首次及末端强制测量当前子目录，节点退出及正式交接前强制测量完整节点范围。

切换工作范围立即重新测量，测量失败不使用旧值放行。不限临时空间仍记录磁盘采样峰值。短于磁盘采样间隔且在边界前删除的瞬时文件不保证被观察到。

长任务使用保持不变的安装环境，源码变更后重新准入，历史 Result 与 holdout 消费记录保持原样。

成功因果键批先完成正式外部提交、核心时间事实检查和完整节点资源验收。系统再追加 `causal-handoffs.jsonl` 交接记录，并释放本批工作副本。记录仅用于交接审计，恢复仍以节点为单位。正式提交和失败批次保留。

保护标记从实际运行根向下生效。保护或清理失败只记录保留原因，不改变已完成批次的金融执行状态。复用 Worker 的任务完成与进程退出分别记录，任务完成后可以释放已交接且不再使用的工作副本。

carry 状态所在批次保留到下一批成功消费并完成交接。后续批次失败时，上一有效状态与当前失败目录一起保留。节点完成时最多保留最后一批状态目录。

正常运行的工作目录数量因此不随成功日期累积。正式输出仍按研究结果保留。

OperatorGraph节点可用resource_profile部分声明memory_bytes、cpu_slots、process_slots、temp_bytes、wall_seconds正整数。未写字段沿算子默认值。准备前摘要、数据预准入、冻结DAG及Workspace使用同一有效预算。

运行总容量独立声明，不随节点覆盖自动提高。覆盖进入计划身份，预算改变后重新准入，旧checkpoint不跨身份复用。

节点可在OperatorGraph声明中显式覆盖单个维度，例如拟合节点：

```yaml
resource_profile:
  memory_bytes: 12884901888
```

该声明将该节点内存设为12 GiB，其余维度沿用算子默认值。运行总容量仍须足以容纳该节点。超过容量时准入拒绝。资源验证以完整阶段的实测峰值为依据。如果探针容忍短时越界，成功结束也不能证明满足更低的硬预算。

### 串行模型的协作资源检查

串行模型拟合检查累计资源峰值和剩余时长。检查发生在每个候选开始前、输入与窗口绑定完成后和候选返回后。已经观察到的超限会终止节点，不作为普通候选拒绝继续训练。检查不重置峰值，checkpoint 发布前仍执行最终资源验收。

这些检查位于同步交接点，不会中断正在运行的一轮训练。并行模型保留原有进程监督与资源检查。

### 资源池状态读取与心跳

公开资源池状态读取与租约更新共用短事务文件锁。读取操作保留租约和状态文件原内容。短事务锁避免 Windows 读取句柄阻挡原子替换。心跳续期失败会保留原始异常。若节点同时失败，节点异常仍为最终错误，心跳异常作为明确原因保留。过期时间和资源验收上限不变。

## 错误处理

| 现象 | 处理方式 |
| --- | --- |
| `runtime_resource_admission` | 读取 `node_id` 和 `exceeded`，调整声明或运行容量。 |
| `project_worker_resource_exceeded` | 按 `actual` 和 `limit` 定位超限维度。 |
| `measurement_unavailable` | 检查测量失败原因，恢复测量后再执行。 |
