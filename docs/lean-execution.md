# LEAN 日线与一分钟策略执行

把研究策略接入本地 LEAN 执行。

## 开始前

- 输入：完整安装、研究包、输入、规则和声明预算。
- 输出：正式执行表、账户终态、指标及报告。
- 命令中的尖括号内容是待替换参数。

## 使用顺序

1. 按安装文档准备独立 LEAN 环境。
2. 填写策略、来源与执行模型。
3. 准入真实输入和规则。
4. 执行研究并等待正式 Result。
5. 直接从 Result 生成报告。

项目策略声明 `execution_backend=lean`，在正式 ResearchPackage 主链中使用本地 LEAN。频率为 `1d` 或 `1m`。数据经过同一 Catalog、PIT 与交易范围准入，选股继续由已准入的因果 Feature 产生。

LEAN 负责账户、订单和撮合。项目策略通过冻结的 Python bundle 接收事件并返回交易意图。

安装与完整包转换命令见[LEAN 接入](../integrations/lean/README.md)。安装脚本位于 `integrations/lean/`，外部插件和宿主位于 `integrations/lean/engine/`，使用固定的本地 LEAN 安装。运行不依赖 Docker。

Windows x64 和 PowerShell 7 的首次安装可从[合成回测示例](../examples/lean_quickstart/README.md)开始，先生成策略包与 Parquet 输入，再安装并执行。使用完整公开源码或解压的 sdist。wheel 只提供 Python 框架。

`run.ps1` 的 `DataDb` 与 `InputSnapshotManifest` 必须二选一，归档分支不连接数据库。当前公开 LEAN 安装流程仅支持 Windows x64 与 PowerShell 7。Linux 核心或模型验收不代表 LEAN 安装可用。

## 声明与输入

准入只检查和冻结输入合同，候选与信号仍在研究节点执行。覆盖证券、候选、持仓和权益的关系见[准入与执行边界](admission-execution.md)。

股票确认退市生效后，剩余股份采用零估值研究假设，保留数量和归零时点，不产生卖出现金。普通停牌或缺价不触发归零。无涨跌幅阶段沿用现有分钟撮合模型，历史市价许可、保护价、数量、资金和T+1约束继续生效。

现货策略参数`lifecycle`按证券代码交接独立生命周期记录，每条包含`delisted_date`（最后存续日）、带时区的`available_at`及`source_ref`。零估值从最后存续日的次日且信息已经可见时生效。窗口末日、会话缺失和停牌不能用作退市日期。

退市生效后保留股份账簿，停止该证券交易。已登记现金权益继续按事件到账，`lifecycle`执行表与账户估值来源保存`delisted_zero`口径。

全部证券在请求终点前退市时，终点增加一次账户观察。消费已登记权益并保存零估值终态，不新增交易日或策略回调。研究收益使用该终态，保留实际`valuation_at`。原始逐日账户仍按原交易日保存。

策略节点同时声明 `execution_backend=lean`、`claim_ceiling=bar_level_research_only` 和完整 `lean_runtime`。一分钟使用 `execution_model=lean_next_completed_close_v1`，日线使用 `lean_next_session_open_v1`，声明频率须与 bars 端口一致。策略声明的 `bundle_id` 必须对应已准入 bundle，输出端口为 `simulation: research.lean-simulation.v2`。

人民币股票使用 `asset_class=cn_stock`、`contract_kind=stock`、`price_scale=2`。ETF 使用 `asset_class=cn_etf`、`contract_kind=etf`、`price_scale=3`。现金金额均按人民币分记账。

ETF 的数量、结算和费用来自冻结的 `cn_fund` 规则。日线与独立开盘来源须在所用 Catalog 中声明并准入。

人民币期货使用`asset_class=cn_future`、真实合约与逐合约价格尺度，按完整历史会话处理夜盘。一个账户内多合约共享资金，同合约保留多空与今昨四桶。期货不使用现货snapshot。独立结算、规则、换月和风险合同见[中国期货执行](lean-futures.md)。

输入为正式 `bars`、逐证券 `snapshot` 和可选 `signals`。行情必须原始未复权、已完成且质量合格。一分钟在分钟结束时可见。

日线按 Catalog 的 `next_session_open` 规则在下一交易日开盘可见。日线直接绑定列式数据请求，以 `bars_request_id` 指定 OHLCV 来源，以 `open_request_id` 指定同证券、同日期的 `session_open` 开盘价来源。两者由同一 data bundle 交接。

历史规则来自包内冻结的 `minute_scope`，公司行动来自正式快照。每条信号保留核心可见时间，同一输入只交付当时最新的完整批次。

行情、逐日规则和当日信号通过本机日数据通道交给引擎。当前交易日执行时，单个读取线程预读下一交易日。预读数据不进入策略当前上下文。

分钟月文件按证券、时间和字段裁剪，每月只扫描一次并在内存中按天组织。月缓存以字典保存重复证券代码，已消费日期释放，跨月释放旧月及 Arrow 池中的空闲页。内存超过声明额度时停止，不生成磁盘交换副本。

行情按有界批次校验、转换和打包，只保留引擎消费的整数字段。价格按不同值十进制 half-up 转换，在本次执行的有界缓存中复用相同报价与精度的转换结果。准备阶段建立规则的有效区间索引，合并共享且不变的参数。每日仍按有效日期及实际可见时间选择完整版本，保留日内变化。

冻结规则恢复按原顺序检查版本流，使用顺序比较检查乱序和重复。避免为全部规则建立排序副本与身份集合。相同标量参数字段有界复用原规范编码字节，完整内容身份仍逐条核对。

现货会话构造复用同次相同窗口的时间文本。日历选版后在已排序交易日中二分定位，历史可见时点与交易日归属不变。

期货分钟按合约批量检查冻结会话边界，每根分钟必须完整落在同一个可交易小节内。夜盘仍归属正式交易日。日通道只序列化一次完整事件头，预算按实际发送头和行情字节数计算，包含日线的可见性声明。引擎按证券查找当日规则，跨日沿用的历史费率仅用于估费，不授予当日交易资格。

信号准备只读取一次各文件结构和决策日期范围，每日仅扫描与该日期相交的文件。没有行组日期统计的文件继续使用正式决策时间过滤。核心时间、证券范围、完整信号批次和内存检查在实际读取时执行。文件索引与价格缓存均不跨运行或恢复复用。

执行工件的 `result.json` 在 `preparation.daily_input_timings` 中按日记录价格转换、打包、通道等待及传输耗时。现货还记录规则组装和信号读取。现货分钟另记录行情读取、范围过滤、分钟标准化及月缓存字节数。

`rule_preparation_seconds` 记录现货规则索引与参数准备。`bars_seconds` 包含标准化、转换与打包，`load_seconds` 包含整个日载荷准备。这些总计与分项有包含关系，不能直接相加。

读取线程与引擎并行，因此 `wait_seconds` 才表示引擎请求后等待载荷的时间。节点摘要另记录输入准备、引擎执行及提交前结果写出耗时。完整流程验收还计入准入、正式提交、Result 封存与报告。

股票与ETF的分钟文件可以包含整个窗口的证券并集。逐日交付先按冻结日历在当时可见的会话版本确定证券范围。再校验该范围内的分钟时间、顺序和价格质量。

尚未进入或已经退出当日范围的证券不交给引擎。该裁剪不改变上市门槛，也不忽略当日合格证券的非法分钟或重复行。

接口接受一个 OHLCV 子集、`lookback_bars>=1` 的行情绑定及至多一个 `lookback_bars=1` 的信号绑定。历史窗口仅包含模拟时钟之前已可见的完整周期。订阅可包含初始化、盘前、完成周期、订单反馈与盘后事件。

策略可以按需读取冻结证券集合内的当时可见报价，实际读取的报价计入上下文额度。策略读取只读账户，提交金额买入、数量买卖或撤单意图。订单为 DAY 市价单。

行情绑定列为 `open`、`high`、`low`、`close`、`volume` 的非空子集。声明包含 `avg` 时在准入阶段拒绝。股票和 ETF 的当日规则交接保留盘中可见版本，包括停复牌和费率。成交按实际时点选择版本。

## 执行与恢复

Workspace execute 合并准备与准入后运行并报告。独立 package lint 保留为主动诊断入口。

项目策略只接受显式声明的 `execution_backend=lean`。历史 RP 策略 Result 保持只读。当前研究使用已准入 LEAN 会话。

独立命令流程使用 `package admit → run → report`。安装锁将实际引擎、插件、策略宿主、配置模板、市场元数据及 .NET/Python 执行依赖的内容身份放入节点参数。正式计划加载和执行前复验这些文件，文件缺失、增加或内容变化均拒绝使用原计划。

已有 LEAN 声明的准备阶段只检查安装锁结构及安装根绑定，不逐个访问安装文件。实际内容检查在 LEAN 节点启动前、跨进程计划加载及恢复时执行：一次调用内复用已解析路径。枚举完整执行闭包并读取全部内容，链接核对实际目标，不跨调用沿用内容验证结论。

节点至少预留三个进程槽：Supervisor、固定启动宿主和 LEAN。Windows 虚拟环境还须为 Python 启动进程增加一个槽。整个进程树受声明的内存、临时空间、CPU、累计时间及单次策略回调额度约束。

Windows Job 在宿主退出时清理后代。引擎退出码、正常完成状态和正式输出均满足后，节点才提交工件。

成功节点沿用现有 checkpoint 恢复合同。中断或失败的 LEAN 节点从该节点重新执行，先前成功的数据与选股节点可按原身份复用。修改引擎安装或桥接实现后须重新准入，不能继续使用旧成功检查点。

运行故障先查看run目录的节点诊断和LEAN日志。安装、实现或输入变化后重新准入到新运行目录，保留原Result及其依赖。

## 结果与金融计算

正式 Result 保存订单、交易意图、日终账户、必要的策略决策和状态、金融指标。以及配置、代码、安装身份和输入版本引用。输入行情与来源保留持久位置。

迁移时一并携带引用依赖。报告直接读取正式表。

日线按最新已可见价格估值：当日 Open 可用时使用 Open。缺 Open 时使用已可见历史价格，除权参考价沿用公司行动规则。每日账户及最终账户保存 `equity_semantics`、`valuation_at` 和逐证券 `valuation_marks`，记录价格来源和可见时间。

该序列不是当日收盘净值。日线指标定义使用 `daily_latest_visible_mark`，报告注明相同口径。一分钟使用执行窗口结束时的已完成行情估值，完整收盘为`session_close_mark`，盘中终态为`execution_window_mark`。

指标频率为`daily_execution_window`。年化仍按观察的交易日期计数，盘中首尾日期的比较限制进入Result和报告。

LEAN的simulation端口交付八张执行表和一张指标表：

| 表目录 | 内容 |
| --- | --- |
| `lean/orders` | 订单事件、成交、费用及对应账户变化 |
| `lean/intents` | 策略交易意图与实际提交数量 |
| `lean/daily` | 逐交易日日终账户与持仓 |
| `lean/trace` | 实际回调、可见报价、应答和状态 |
| `lean/fills` | 期货实际成交腿、开平、方向桶、费用与实现盈亏 |
| `lean/positions` | 期货方向与今昨桶快照 |
| `lean/account_events` | 期货权益、现金、浮盈亏、保证金、冻结及可用资金 |
| `lean/lifecycle` | 期货预占释放、结算、风险、换月与退出事件 |
| `lean/metrics` | 金融指标、定义、单位及样本范围 |

支持文件包括`lean/account.json`、`lean/strategy-state.json`、`lean/runtime-lock.json`、`lean/strategy-input.json`，以及引擎终态与Launcher摘要。行情、历史规则、公司行动和信号输入通过持久工件与计划引用保留。迁移、归档或清理时同时保留这些依赖。项目绑定signals时，ResultSpec继续选择实际Feature producer的正式源表，该表属于上游输出。

输入准备检查正式 PIT 快照并保存小型来源清单、策略输入、公司行动及市场元数据。行情与逐日规则在执行时读取和传输。必要金融事实按执行需要投影，来源身份保留在原准入输入及持久工件中。

研究DAG由实际数据、模型或策略计算节点组成，成功后发布Result。模型最终评价继续记录持久holdout账本，实际读取前登记消费。报告直接使用正式指标和执行表。

LEAN 与冻结的中国市场规则在下单、成交及账本转换处执行金融检查。检查包括信号和行情可见性、后续分钟成交、滑点、费用和参与率。数量格点、保护价、T+1、可用现金和日终权益也参与检查。回调账户区分持仓、可卖数量、活动订单与扣除金额买单预占后的现金。

现金红利按登记日持仓确认权益，付款后进入现金。整数送转分别按股份到账和可卖时点处理。应收红利、待到账和锁定股份使用当时可见价格估值。开发验收用手算案例检查登记后卖出、跨日到账、费用和购买力边界。

股票快照算子`data.minute.adjustment_snapshot`的`financial_missing_date_policy`默认为`error`，非零权益缺日期时拒绝。研究包可显式声明`omit_event`：派息日为空时不生成现金分红事件。红股或转增的到账日、股份上市日任一为空时，不生成对应送转权益事件。

现金、红股、转增分别处理，其他日期完整的权益继续执行。空金额和比例仍按零处理，非空但无效的日期与缺失来源继续拒绝。该参数不适用于ETF。

`omit_event`只改变账户金融权益，除权和PIT复权仍使用原始非零分配信息。参数随计划冻结并改变节点配置身份，正式Result的`limitations`记录忽略空日期权益的假设。收益和持仓不包含被忽略的分配，历史Result与检查点保持原身份。

金融指标包含收益、回撤、波动、夏普、换手、费用及交易数量。收益含首日相对期初资金的变化，回撤使用含期初资金的运行峰值。年化使用252个交易日，夏普采用零无风险利率。定义、单位和样本随 Result 保存，算法更改使用确定性案例验收。

HTML报告展示净值、回撤、成交和费用。将正式Result ID与表ID写入请求文件：

```json
  "result_id": "<正式Result ID>",

  "budget": {"max_rows": 100000, "memory_bytes": 268435456}

```

```powershell

  --output '<报告HTML>' --summary
```

Markdown和JSON报告沿用同一正式指标入口，不需要HTML请求文件。

## 已知限制

- 一分钟按后续完成分钟 Close 加声明滑点成交。日线按下一交易日已可见开盘价成交。日线账户估值记录价格来源和时间，不等同于当日收盘净值。
- 当前支持已准入人民币股票、ETF与真实期货合约的日线和一分钟。不接受其他周期或定时事件。行情历史窗口必须显式声明。现货订单为DAY市价，期货订单支持market/limit和DAY/IOC。
- 不保存可跨进程接续的 LEAN 内部状态。节点失败时重新执行整个节点。
- 公司行动支持毛额现金分红和整数送转。个人红利税、非整数股份分配及其他行动类型需要独立合同。
- 日行情与逐日规则通过内存数据流交接。日志和构建缓存按生命周期规则处理。正式 Result、模型、holdout 账本、冻结声明与恢复工件须保留。直接来源运行依赖原数据库和行情文件。


## 常用名称

| 名称 | 含义 |
| --- | --- |
| ResearchPackage | 数据、算法、样本、指标和预算的完整声明 |
| Catalog Lock | 已确认的字段、来源和可见性说明 |
| PIT（按时点可见） | 过去某时刻只使用当时已知的信息 |
| bar（周期行情） | 一个日线或分钟区间的行情记录 |
| OHLCV（开高低收量） | 开盘价、最高价、最低价、收盘价和成交量 |
| Feature（特征） | 决策时已知的研究输入 |
| Label（标签） | 用于评价预测的未来目标 |
| bundle（封存包） | 完整代码、依赖或数据声明及其内容身份 |
| checkpoint（检查点） | 通过验收的节点输出和恢复依据 |
| Result（正式结果包） | 正式表、运行摘要及配置、实现和输入引用 |
| minute_scope（分钟范围引用） | 指向同一冻结日历和历史规则的小引用 |
| Supervisor | 监督运行和提交结果的主进程 |
| Worker | 执行节点计算的独立进程 |
