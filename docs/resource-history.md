# 资源治理的活动状态与历史

## 开始前

- 只在跨进程共享容量时启用共享资源池。
- 为 `--resource-state-dir` 指定仓库外目录。
- 让同一共享池的调用声明相同容量。
- 保留状态文件和租约历史日志。

先进先出（FIFO）表示按申请顺序分配资源。
租约是运行占用资源额度的记录。
Supervisor 负责监督执行，Worker 负责节点计算。
驻留内存（RSS）表示进程占用的物理内存。

## 使用流程

1. 在运行命令中指定 `--resource-state-dir`。
2. 对共享调用使用同一目录和容量。
3. 从正式运行回执检查资源测量状态。
4. 在写入进程停止后整体保存资源池目录。

共享池协调跨进程 FIFO 申请、活动租约和父子额度。普通单次运行使用进程内容量。节点实际测量记录在本次运行的 checkpoint 事件中。

## 状态目录与版本

共享状态使用 `research-resource-governor-v4`。启用时指定新的仓库外目录，历史池目录独立保留。

| 文件 | 内容 | 读取时机 |
| --- | --- | --- |
| `resource-governor.json` | 配置身份、容量、申请序号、待处理申请、活动租约、租约历史日志的提交位置 | 申请、心跳、释放、回收和状态消费者 |
| `lease-history.jsonl` | 已结束租约及其释放或回收原因 | 完整租约快照、只读状态展示、重复释放的身份核对 |
| `resource-governor.lock` | 现有跨进程排他锁 | 修改共享状态时 |

活动状态中的 `history` 保存 `bytes` 与 `records`。前者是日志已提交前缀的字节长度，后者是该前缀包含的记录数。日志逐行保存配置身份、连续序号和记录内容。心跳不打开历史日志。

## 提交与中断

所有状态修改沿用同一把跨进程锁。结束租约按以下顺序提交。

- 系统从活动状态读取对应日志的已提交位置。
- 系统在提交位置后追加历史记录，再刷新缓冲区并 `fsync`。
- 系统将活动状态和日志提交位置写入临时状态文件。
- 系统刷新临时状态文件并 `fsync`。
- 系统原子替换 `resource-governor.json`。

活动状态文件替换是本次操作的提交点。父租约及其活动后代的关闭记录在同次状态提交中可见，额度释放与结束历史一起生效。

历史追加或状态替换中断时，原活动状态文件继续指向此前有效前缀。消费者只读取该前缀，不把未提交尾部当作已发生的释放。下一次对应日志的写入从已提交位置继续，截去未提交尾部，原有效前缀保持不变。已提交日志缺失、变短或记录不完整时明确拒绝，不用空历史替代。

恢复仍通过同一共享目录重新构造 governor。不要单独替换活动状态文件或任意日志。需要留存共享池时，应在写者停止后一起保存这些状态文件。

## 历史验证

状态操作验证当前配置身份、活动记录和容量守恒。实际读取历史的消费者同时验证日志封装、配置归属、连续序号、完整行与记录数。

租约历史还会验证完整租约 schema、原 lease_id、进程身份字段和结束状态。快照保留结束记录，重复释放仍核对身份。全局守恒、FIFO、父子额度、PID 与进程创建时间、陈旧回收规则保持原有语义。

## 项目 Worker 的采样交接

启用治理时，项目 Supervisor 与 governor 共享本轮真实测量：

- Supervisor 监督循环接管期间，当前 attempt 的后台采样暂停重复扫描。
- 一次进程测量覆盖 Supervisor、Worker 和已观察到的存活后代。后代身份继续以 PID 和创建时间核对。
- 重叠 scratch 根只遍历一次，每个文件只读取一次大小。项目 attempt、Worker session 和 checkpoint 范围分别记账。
- 同一读数用于 RSS、临时空间和进程槽硬门禁，与本次运行的峰值记录。测量失败仍记为 `measurement_unavailable` 并阻断成功。
- 交接退出后恢复后台采样，包括异常退出。注册按线程和 attempt 范围匹配，嵌套交接退出后恢复外层归属。

这项交接不缓存过期读数，不延长节点 deadline。RSS、temp、进程槽或 deadline 超限时，监督器仍终止 Worker 并清理已观察后代。Worker 的 Windows 生命周期作业绑定继续生效。项目计算结束后，治理采样继续覆盖 checkpoint 暂存、发布与最终资源验收。

## 已知边界

- 完整租约快照按需读取历史，其成本随历史增长。心跳成本随活动申请和活动租约增长。
- 历史不自动清理或压缩，不跨版本恢复旧共享池。旧目录应独立保留。
- 进程槽按实际 `sys.executable` 层级计数。计数包括 Supervisor、Worker 解释器、虚拟环境启动器和冷启动辅助进程。禁止仅按操作系统指定固定下限。额外项目子进程仍计入同一上限。

## 错误处理

| 现象 | 处理方式 |
| --- | --- |
| 共享池容量不符 | 改用容量一致的池目录。 |
| 已提交日志缺失或变短 | 恢复完整状态文件和日志。 |
| 心跳失败 | 检查原始异常及共享目录访问状态。 |
