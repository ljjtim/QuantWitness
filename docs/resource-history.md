# 资源治理的活动状态与历史

共享资源治理仅在显式提供仓库外的 `--resource-state-dir` 时启用。普通单次运行继续使用进程内容量。共享池协调跨进程 FIFO 申请、活动租约和父子额度，历史观测用于事后校准，不会自动改变后续 reservation。

## 状态目录与版本

共享状态使用 `research-resource-governor-v3`。启用 v3 时必须指定新的仓库外目录；v2 状态不迁移、不改写，也不能直接作为 v3 的输入。资源观测内容仍为 `research-resource-observation-v4`。

| 文件 | 内容 | 读取时机 |
| --- | --- | --- |
| `resource-governor.json` | 配置身份、容量、申请序号、待处理申请、活动租约、两份历史日志的提交位置 | 申请、心跳、释放、回收和状态消费者 |
| `lease-history.jsonl` | 已结束租约及其释放或回收原因 | 完整租约快照、只读状态展示、重复释放的身份核对 |
| `observations.jsonl` | 资源观测及原有 observation_id | 观测登记与去重、校准、独立校准工具 |
| `resource-governor.lock` | 现有跨进程排他锁 | 修改共享状态时 |

热状态中的 `history.leases` 和 `history.observations` 各保存 `bytes` 与 `records`。前者是日志已提交前缀的字节长度，后者是该前缀包含的记录数。日志逐行保存配置身份、连续序号和记录内容。心跳不打开历史日志，也不遍历结束租约或重验历史观测。

## 提交与中断

所有状态修改沿用同一把跨进程锁。结束租约和观测的提交顺序为：

1. 从热状态读取对应日志的已提交位置。
2. 在该位置后追加冷记录，刷新缓冲区并 fsync。
3. 将更新后的活动状态和日志提交位置写入热文件的临时文件，刷新并 fsync。
4. 原子替换 `resource-governor.json`。

热文件替换是本次操作的提交点。父租约及其活动后代的关闭记录在同次热提交中可见，额度释放与结束历史一起生效。

冷追加或热替换中断时，原热文件继续指向此前有效前缀。消费者只读取该前缀，不把未提交尾部当作已发生的释放或观测。下一次对应日志的写入从已提交位置继续，截去未提交尾部，原有效前缀保持不变。已提交日志缺失、变短或记录不完整时明确拒绝，不用空历史替代。

恢复仍通过同一共享目录重新构造 governor。不要单独替换热文件或任意一份日志；需要留存共享池时，应在写者停止后一起保存这些状态文件。

## 历史验证与校准

热操作验证当前配置身份、活动记录和容量守恒。实际读取历史的消费者同时验证日志封装、配置归属、连续序号、完整行与记录数。

租约历史还会验证完整租约 schema、原 lease_id、进程身份字段和结束状态；快照保留结束记录，重复释放仍核对身份。全局守恒、FIFO、父子额度、PID 与进程创建时间、陈旧回收规则保持原有语义。

观测消费者逐条验证 v4 schema、数据规模桶、时间、实际与估算分量及原 observation_id；重复身份不能出现两条记录。观测损坏会阻止登记和校准，但不让心跳承担全历史扫描。

只有身份匹配、测量可用、非 fixture 的真实成功观测进入校准。失败、取消、测量不可用和探针继续排除。样本数门槛与 nearest-rank 分位数保持原有定义。

独立校准入口为 `tools/resource_governance_oracle.py`。它独立读取 v3 热状态与已提交观测前缀，复验观测身份和规模桶，再计算分位数，不导入生产校准实现。

## 项目 Worker 的采样交接

启用治理时，项目 Supervisor 与 governor 共享本轮真实测量：

- Supervisor 监督循环接管期间，当前 attempt 的后台采样暂停重复扫描。
- 一次进程测量覆盖 Supervisor、Worker 和已观察到的存活后代；后代身份继续以 PID 和创建时间核对。
- 重叠 scratch 根只遍历一次，每个文件只读取一次大小；项目 attempt、Worker session 和 checkpoint 范围分别记账。
- 同一读数用于 RSS、临时空间和进程槽硬门禁，以及 governor 的峰值观测。测量失败仍记为 `measurement_unavailable` 并阻断成功。
- 交接退出后恢复后台采样，包括异常退出；注册按线程和 attempt 范围匹配，嵌套交接退出后恢复外层归属。

这项交接不缓存过期读数，不延长节点 deadline。RSS、temp、进程槽或 deadline 超限时，监督器仍终止 Worker 并清理已观察后代。Worker 的 Windows 生命周期作业绑定继续生效。项目计算结束后，治理采样继续覆盖 checkpoint 暂存、发布与最终资源验收。

## 已知边界

- 完整租约快照、观测登记与校准按需读取相关历史，其成本仍随该历史增长；心跳成本随活动申请和活动租约增长。
- 历史不自动清理或压缩，不跨版本恢复旧共享池；旧目录应独立保留。
- 进程槽需按实际 `sys.executable` 层级计入 Supervisor、Worker 解释器、虚拟环境启动器和冷启动辅助进程，不能仅按操作系统指定固定下限；额外项目子进程仍计入同一上限。
