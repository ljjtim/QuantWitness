# 研究执行与结果交付

从进程状态定位到正式结果和报告。

## 开始前

- 输入：研究包、当前计划和实际运行记录。
- 输出：可解释的执行状态与正式交付物。
- 命令中的尖括号内容是待替换参数。

## 使用顺序

1. 通过 Workspace 或正式运行入口开始研究。
2. 用真实计数判断进度。
3. 根据错误与恢复建议处理故障。
4. 直接读取已发布 Result。

框架分别记录进程存活、真实进展和Result发布。普通Workspace execute合并准备与准入，随后运行、发布Result并报告。独立package lint用于主动诊断。

## 执行与恢复

- [真实进度](runtime-progress.md)区分心跳、已提交节点与成功因果批，ETA只覆盖样本充分的当前阶段。
- [Workspace接续](workspace-continuation.md)使用原execution、plan、invocation与Result，报告失败不重新训练或消费holdout。
- [资源预算](project_resource_budgets.md)区分节点声明、已知输入体积与实测峰值。缺少依据时保持unknown，不自动加额度。
- 输入和中间产物按实际消费者交接。正式结果保留配置、代码和输入版本引用，原始数据依赖有持久位置。
- [身份范围](implementation-identity-scope.md)区分局部源码、共享依赖和恢复环境，真实依赖变化拒绝旧checkpoint。

## 正式结果

当前股票和ETF日线、一分钟策略由LEAN执行。日频模型使用split、fit、predict、metrics、selection、holdout六节点。正式Result供报告、比较、分析、导出及AI开发反馈直接消费。

全部节点成功但Result尚未发布时，原resume只重试组装。Result发布后报告失败，保留执行成功和原Result，单独生成报告即可。最终holdout的已打开区间和失败消费记录继续有效。

## 开发验收与测量

算法和金融转换用确定性案例、手算输入和必要的差分对照检查。PIT、Label读取、holdout和资金规则在实际消费者处执行。

性能记录采用相同版本、输入、预算和缓存条件。区分准入、输入准备、计算、正式提交、Result封存与报告耗时。RSS、临时空间、文件数和字节使用实际测量。

局部编码或读取速度不能代替完整流程耗时。长任务使用保持不变的安装环境。


## 常用名称

| 名称 | 含义 |
| --- | --- |
| ResearchPackage | 数据、算法、样本、指标和资源的完整研究声明 |
| Catalog Lock | 已确认的数据字段、来源和可见性说明 |
| PIT（按时点可见） | 在过去某时刻只使用当时已知的信息 |
| QueryIR | 限定字段、范围、排序和预算的数据请求 |
| DAG（计算步骤图） | 节点之间的先后依赖 |
| Artifact（工件） | 带类型、内容身份和来源引用的产物 |
| checkpoint（检查点） | 通过正式验收的节点输出及恢复依据 |
| Result（正式结果包） | 正式表、运行摘要和配置、实现、输入引用 |
| holdout（最终留出集） | 开发选择之外的最终评价区间 |
| Supervisor | 监督执行、发布检查点和记录事件的主进程 |
| Worker | 执行节点计算的独立进程 |
| manifest（清单） | 记录文件、类型、范围和内容身份的文件 |
| schema（结构） | 表的字段名称、类型和约束 |
