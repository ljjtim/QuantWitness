# 研究执行与结果交付

框架分别记录进程存活、真实进展和 Result 发布。普通 Workspace execute 合并准备与准入，随后运行、发布 Result 并报告；独立 package lint 保留为主动诊断。

## 执行与恢复

- [真实进度](runtime-progress.md)区分心跳、已提交节点与成功因果批，ETA 只覆盖样本充分的当前阶段。
- [Workspace 接续](workspace-continuation.md)使用原 execution、plan、invocation 与 Result，报告失败不重新训练或消费 holdout。
- [资源预算](project_resource_budgets.md)展示节点声明、已知输入体积与实测峰值；缺少依据时保持 unknown，不自动加额度。
- 输入和中间产物按实际消费者交接，正式结果保留配置、代码和输入版本引用；原始数据依赖有持久位置。
- [身份范围](implementation-identity-scope.md)区分局部源码、共享依赖和恢复环境，真实依赖变化拒绝旧 checkpoint。

## 开发验收

算法和金融转换用确定性案例、手算输入和必要的差分对照检查。生产 PIT、Label 读取、holdout 和资金规则保留在实际消费者。Result 直接报告、比较、导出和反馈，不另设每轮事后复算阶段。

## 已知限制

历史微基准不是端到端耗时。当前流程的耗时、RSS、临时空间、文件数和字节须在相同版本、输入、预算与缓存条件下实测。Arrow 输入与必要索引仍占内存，保持不变的安装环境用于长任务。
