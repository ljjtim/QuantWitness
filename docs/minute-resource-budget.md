# 分钟分区预算与调度

为分钟分区分配临时空间并处理失败。

## 开始前

- 输入：节点临时预算、并发数及可选资源租约。
- 输出：分区提交、预算回执与可恢复记录。
- 命令中的尖括号内容是待替换参数。

## 使用顺序

1. 声明节点预算和 `worker_count`。
2. 按并发数计算单分区上限。
3. 执行有界分区调度。
4. 检查失败和成功分区记录。
5. 沿同一身份恢复未完成分区。

`MinutePartitionRuntime.execute` 的 `max_temp_bytes` 由本次声明的 `worker_count` 共同使用。单分区临时空间验收上限为 `max_temp_bytes // worker_count`，余数不分配。

启用 `ResourceGovernor` 且并行执行时，实际验收上限还受已取得的子租约 `scratch_bytes` 限制，取两者最小值。单 worker 直接使用父租约，取节点临时预算与父租约 scratch 的最小值。未启用 Governor 的并行执行仍按 worker 数分配节点临时预算。

例如，节点临时预算为 100 字节、并发数为 2 时，每个分区最多使用 50 字节。任一分区使用 75 字节都会以 `minute_runtime_budget_exceeded` 拒绝，不发布该分区的成功 checkpoint。父租约若只有 60 字节，每个子分区上限进一步降为 30 字节。父租约更大也不能提高节点声明的上限。

`temp_bytes` 继续记录单分区 action 返回时 staging 目录的实际文件字节数。`worker_count`、输出大小、工件语义和返回结构保持原有含义。已完成分区的临时字节数不能相加作为并发峰值。

六个分区分三批运行、每个使用 50 字节，可以在并发数 2、节点临时预算 100 字节下完成。已提交工件受独立的 `max_output_bytes` 总量限制。

## 有限在途调度与失败恢复

并行执行只保留最多 `worker_count` 个已提交且尚未收取结果的任务。任一分区完成后，先处理本批全部完成结果。全部成功才补交后续分区。返回的 commits、metrics 和语义摘要仍按原 manifest 顺序构造，与分区完成顺序无关。

发现分区失败、预算拒绝或调度中断后，停止补交并取消尚未开始的任务。已运行的线程继续到退出。通过原资源和工件检查的分区仍可发布成功 checkpoint。执行器等待这些线程结束后才返回失败并把运行记录标记为 `paused`，不会在返回后继续写入。

使用同一身份显式 `resume=True` 时，复验并复用已成功 checkpoint，只执行失败和未完成分区。缺失或损坏的工件继续按原恢复规则拒绝。

## 已知边界

单分区验收在 action 返回后执行，不是操作系统磁盘硬限额，也不测量 action 内已经删除文件的瞬时峰值。Governor 的外层采样合同保持原样。并发分配按声明 worker 数计算，不因尾批任务少而自动放宽。

取消不能抢占已经运行的线程。返回后时限检查与 action 前后 RSS 采样也不是运行中硬终止或全程峰值测量。需要运行中超时终止的任务使用现有独立 Worker。

源码变化会影响包含该运行器的实现身份。恢复和共享源码基线由正式身份合同处理，历史 Result 保持原样。


## 常用名称

| 名称 | 含义 |
| --- | --- |
| ResearchPackage | 数据、算法、样本、指标和预算的完整声明 |
| Catalog Lock | 已确认的字段、来源和可见性说明 |
| PIT（按时点可见） | 过去某时刻只使用当时已知的信息 |
| bar（周期行情） | 一个日线或分钟区间的行情记录 |
| OHLCV（开高低收量） | 开盘价、最高价、最低价、收盘价和成交量 |
| Feature（特征） | 决策时已知的研究输入 |
| Label（标签） | 用于评价预测的未来目标 |
| bundle（封存包） | 完整代码、依赖或数据声明及其内容身份 |
| checkpoint（检查点） | 通过验收的节点输出和恢复依据 |
| Result（正式结果包） | 正式表、运行摘要及配置、实现和输入引用 |
| minute_scope（分钟范围引用） | 指向同一冻结日历和历史规则的小引用 |
| Supervisor | 监督运行和提交结果的主进程 |
| Worker | 执行节点计算的独立进程 |
