# 直接读取研究输入

选择直接读取来源，或显式保存普通查询输入。

## 开始前

- 输入：当前准入计划和可读取的原始来源。
- 输出：直接引用、读取记录和正式计算结果。
- 命令中的尖括号内容是待替换参数。

## 使用顺序

1. 按恢复和归档需要选择输入保存方式。
2. 为日线、一分钟及日历填写真实来源。
3. 运行研究包。
4. 保留首次调用的输入选择和来源身份。
5. 同时保存 Result 和实际依赖。

普通数据请求默认创建来源引用，消费者按需从只读 DuckDB 或已有 Parquet 归档读取。来源描述保存准入计划、字段、日期范围、执行估算和来源修订身份，不复制查询结果。直接引用与已保存的物理快照使用不同合同。Result 记录实际来源类型。

直接引用创建时不预扫全部数据，也不生成 `data.row_count` 精确行数指标。研究包若要求该物化指标，应显式保存输入。消费节点的实际读取行数按其运行记录提供。

普通来源按请求投影补齐质量检查所需的主键和事件时间。只有声明了证券轴时才追加证券字段。交易日历等无证券轴来源沿用相同的日期、主键及预算检查。数据库直接读取与归档直接读取保持一致。

## 保存与恢复

`run`、`workspace run`、`workspace execute` 可显式传入 `--persist-inputs`，将普通查询输入保存为列式工件。不传该选项时使用直接来源。该选择随首次运行调用冻结，恢复保持原选择。

直接引用依赖原数据库或归档位置。执行和恢复检查来源修订。来源变化时须重新准入，不把新数据接入旧检查点。

移动或清理运行目录时同时保留引用的来源。报告直接读取正式 Result，无须重新读取行情。

正式 Result、模型、运行计划、必要诊断以及持久 holdout 账本继续保存。最终评价已经打开的区间保持已消费状态。

## 日线与一分钟

分钟准入通过`--minute-data-root`读取所选月文件的元数据，冻结路径、实际schema、来源修订及声明预算。运行节点共用该扫描计划，恢复核对原来源。QueryIR的半开结束时间与`as_of`共同决定有效范围，分区、会话及运行日期保持一致。职责和持仓依赖见[准入与执行边界](admission-execution.md)。

公开研究周期为 `1d` 和 `1m`。分钟行情、特征和标签只接受 `interval_minutes=1`，不生成多分钟派生行情。日线直接查询日频源。

一分钟直接读取原分钟月文件。月文件按证券、字段与请求时间裁剪，在内存中按交易日组织，同月后续交易日不重复扫描整月。当前日执行与下一交易日预读重叠，读完的日期释放，跨月释放旧月。

行情和逐日规则通过本机内存数据通道交接。内存额度覆盖当前日、预读日及读取缓存。超过声明额度时失败，不写交换文件。读取统计保留月扫描次数、行组数和行数。

月缓存压缩重复证券代码，跨月释放旧月和空闲 Arrow 内存。行情逐批转换、逐批打包。日信号文件的结构与日期范围在本次执行中只准备一次。

实际交付仍按决策日和核心可见时间过滤。分项耗时见[LEAN 执行诊断](lean-execution.md)。

预读只改变读取时机。策略行情窗口仍受模拟时钟与 Catalog 可见规则限制：一分钟在完成后可见。日线按 `next_session_open` 在下一交易日开盘可见。

撮合只能使用成交时已知的信息。规则、公司行动、信号和历史窗口继续按消费时点裁剪。

声明、执行模型及结果表见 [LEAN 执行](lean-execution.md)。

## 期货分钟 Feature 与 Label 的日历

独立项目 Feature／Label 直接消费 `data.minute.scan` 时，使用自身节点显式声明的
`minute_scope`。普通 `data.minute.scan → research.bars.minute_resample → 项目分区消费者`
同样要求项目消费者自身声明与行情同源的 `minute_scope`，缺少或冲突时在准备阶段拒绝。项目算子的参数声明必须允许该 JSON 参数，节点再填写对应引用。

仅在节点
增加字段、而 bundle 未声明参数，会被参数校验拒绝。例如，算子薄声明的参数列表包含：

```yaml
parameters:
  - {name: causal_plan, value_type: json, required: true}
  - {name: minute_scope, value_type: json, required: true}
```

研究包中对应 Feature／Label 节点的参数使用本包实际生成的引用：

```yaml
parameters:
  minute_scope:
    contract_version: minute-scope-input-v1
    name: market
    calendar_hash: <本包冻结日历身份>
    rules_hash: <本包冻结规则身份>
  causal_plan:
    # sources与work_items沿用正式因果声明。
    ...
```

准备阶段按 `causal_plan.sources[].request_id` 绑定日历，检查请求证券、有效起止、夜盘及
历史可见版本。缺少自身声明或完整覆盖时拒绝。同一请求不能绑定不同 scope，不从策略
节点推断独立 Feature／Label 的来源。

当前 `minute-scan-plan-v2` 冻结 scope 小引用和准入来源时区，扫描 lineage 保留同一来源。持久计划加载及 Worker 同时核对扫描引用、节点冻结参数和实际日历内容。普通分区路径由
父进程从冻结环境交接来源根与引用，不把路径或大日历写入公用行情工件。

Worker 仅读取
scope 的证券、时段和政策列式文件，不解码规则表。同组分区共用已核对的日历。

raw 分钟 `dt` 是来源墙钟。会话解析按已准入来源时区定位，夜盘归属冻结日历声明的交易日，
不能把墙钟整数当作 UTC。项目日历使用其实际政策 ID，并在会话开盘及分钟时点允许的范围内
选择可见 revision。

未来才可见的版本不能提前生效。参考样本不作为默认日历。

旧扫描计划不跨当前合同恢复。历史研究工件保持只读，需要执行时按当前声明重新准入。

显式 `stateless_session` 的因果 Worker 在节点会话内复用归档来源的首次完整验证。复用仍绑定同一直接来源描述、原准入计划和实际归档引用。每次读取核对已绑定数据文件、
manifest 与提交标记的大小及修改时间，来源变化时拒绝继续。

窗口、投影、排序、质量检查
和实际交付时间轨迹仍逐批执行。验证会话不写入 checkpoint，也不跨节点或进程恢复。

归档有序扫描在同一验证生命周期内复用真实 Parquet footer。扫描按冻结过滤表达式裁剪不相交的文件和行组，再读取业务列。裁剪不依赖目录或文件名。

缺少统计的行组继续扫描，
命中行组保留原文件顺序和原过滤规则。footer索引复用前仍核对实际文件是否变化。

同一验证会话还复用已验Direct描述及其归档绑定。描述文件变化或准入计划内容变化时拒绝。
复用不改变全局计划身份算法，也不跨运行保存。普通直接读取在同一已解析对象内复用
归档计划核对结果，实际来源绑定仍在扫描前后检查。

### 模型表逻辑验收复用

同一次串行运行内，模型消费者共用正式工件验证会话。首次消费仍完整核对表的逻辑记录身份。验收成功后，后续节点可在同一正式commit、真实目录、文件状态及表声明内复用结果，再按fold投影读取。

文件修改、替换或声明变化会拒绝复用。直接调用开发reader而没有正式工件绑定时仍完整验收。缓存不写入计划或checkpoint，也不跨运行复用。

`bounded_parallel` 的隔离节点不共享模型表逻辑验收缓存，包括 `workers=1`。每个计算进程保持首次完整逻辑验收，不通过跨进程代理传递新的缓存证明。节点退出后释放其工作集。串行主进程内的消费者仍可共享同一次运行已完成的逻辑验收。


## 常用名称

| 名称 | 含义 |
| --- | --- |
| ResearchPackage | 数据、算法、样本、指标和资源的完整研究声明 |
| Catalog Lock | 已确认的数据字段、来源和可见性说明 |
| PIT（按时点可见） | 在过去某时刻只使用当时已知的信息 |
| QueryIR | 限定字段、范围、排序和预算的数据请求 |
| DAG（计算步骤图） | 节点之间的先后依赖 |
| Artifact（工件） | 带类型、内容身份和来源引用的产物 |
| checkpoint（检查点） | 通过正式验收的节点输出及恢复依据 |
| Result（正式结果包） | 正式表、运行摘要和配置、实现、输入引用 |
| holdout（最终留出集） | 开发选择之外的最终评价区间 |
| Supervisor | 监督执行、发布检查点和记录事件的主进程 |
| Worker | 执行节点计算的独立进程 |
| manifest（清单） | 记录文件、类型、范围和内容身份的文件 |
| schema（结构） | 表的字段名称、类型和约束 |
