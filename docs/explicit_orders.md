# 显式订单：何时提交，如何占用资金

目标持仓表达“我想持有多少”；显式订单表达“现在提交哪一单”。当你要研究限价、撤单、剩余量或订单有效期时，需要显式订单。

预占表示这笔现金或持仓已经为订单留出，不能被另一单重复使用；它与实际成交后的扣款分开记录。

内部策略会话通过同一显式订单执行器提交动态命令，账户、撮合、费用和订单状态仍由现有内核处理；策略入口的范围与现金预占规则见[策略事件协议](strategy-protocol.md)。当前公共execution_mode仍为本文的预声明模式。

## 参数与行为说明

ResearchPackage 的分钟和日频现金仿真节点可通过 `execution_mode: explicit_orders` 接收已冻结的订单命令。`order_commands` 是至少包含一条 `submit` 的完整 JSON 数组字符串；省略两个参数时沿用 `target` 模式。目标模式逐 Bar 调和并生成独立 IOC；显式模式由同一订单编号承接后续执行机会。

`targets` 输入端口保留。显式模式要求有类型的空目标表，保留原数据来源、PIT 和公司行动元数据；非空目标和显式命令同时输入会被拒绝。项目可通过已经准入的 ProjectOperator 发布该工件，不能修改已提交工件或跳过来源准入。

日频期货 Python 入口 `run_futures_daily_simulation` 使用 `execution_mode="explicit_orders"` 和 `order_commands`；独立品种组合使用 `order_commands_by_product`。命令不得与非空 intents 同时输入；组合内命令编号和提交订单编号须全局唯一。原 intents 模式保留。

## 命令

`research_pipeline.domain.order_stream.ExplicitOrderCommand` 是不可变合同，`to_dict()` 返回完整字段，`parse_order_commands()` 校验并恢复命令流。

| 字段 | 含义 |
| --- | --- |
| `command_id`、`order_id` | 命令唯一身份、订单唯一身份；撤单引用原订单 |
| `action` | `submit` 或 `cancel` |
| `instrument` | 真实证券／合约的 InstrumentKey |
| `decision_time`、`submitted_at`、`available_at` | 决策、提交及输入可见时点，均须带时区；决策及可见时点不能晚于提交 |
| `source_sequence`、`source_hashes` | 同时点稳定顺序，以及冻结来源引用 |
| `trading_date` | 明确的交易会话日期，期货夜盘沿交易日归属 |
| `side`、`quantity`、`position_effect` | 方向、正整数数量、开平类型；现货为 `auto`，期货显式开平 |
| `order_type`、`time_in_force` | `market`／`limit` × `IOC`／`DAY` |
| `limit_price` | 限价单必须提供；市价单为空 |
| `reference_price`、`reference_price_available_at` | 决策时已可见的参考价及可见时点，同时用于预占和 TCA 决策基准 |
| `funds_policy` | `reject` 拒绝不足资金，或 `resize` 在合法数量格点内缩量 |
| `slippage_bps`、`slippage_ticks` | 非负价格比例及最小报价单位滑点，按方向舍入 |

参考价须满足 `reference_price_available_at <= decision_time <= submitted_at`。决策后才可见的价格即使在提交前已经可见，也不能作为该订单的决策基准；分钟和日频 Runtime 均在命令解析时拒绝。延迟提交保留原决策基准及其可见时点。

撤单仅携带身份、标的、交易会话、时钟和来源；交易字段为空，滑点为零。命令流必须按 `(submitted_at, source_sequence)` 排序，命令编号唯一，提交订单编号唯一，撤单须引用此前提交的同一标的订单。撤单到达时原订单已经终结，会记录 `order_not_active` 拒绝请求，账户和原成交保持不变。

## 成交与费用

显式命令在提交后才参与合格执行事件。分钟仍按下一 eligible completed bar 执行，不能以盘中提交时未收盘的完整 Bar 回溯成交；日频仍使用开盘时可见事实或显式声明的无界容量假设。限价按执行参考价及滑点判断，不根据 high/low 推测未知盘中路径，不把越界价格截回限价制造成交。

同标的同一执行 Bar 的全部订单共享容量。IOC 在首次合格机会结束后取消余量；DAY 保留余量，直至全部成交、撤单或该交易会话结束。股票和 ETF 遵守历史数量格点及可卖限制；期货夜盘不会在自然日零点自动到期。

最低佣金按 `order_id` 的已确认成交累计。第二笔成交只补足累计应扣与已扣的差额；手续费试算不改变累计值。税费按每笔实际成交时规则计算，费率修订不重算旧成交。未成交不收佣金；部分成交后撤单保留已发生费用。

## 唯一账本与证据

Broker 保存订单生命周期，Ledger 按订单保存现金、保证金、可卖和可平今昨仓预占。预占不改变总权益和持仓数量；卖出款可能不足最低手续费时，预占相应现金差额；成交只能使用本单预占及未被其他订单占用的余额。部分成交重算剩余预占，撤单及到期释放本单余额。

Result 保留规范六表、订单生命周期、原始命令、提交规则、执行观察、金融事件和逐笔累计费用。规范订单表继续使用 `filled`、`partially_filled`、`rejected` 成交摘要；`cancelled`、`expired` 等终态由生命周期表表达。报告及导出直接消费同一 Result，金融约束在实际执行和账本转换处检查。

新增命令和执行实现进入计划身份。新输入或实现变化需重新准入；历史 Result 只读，恢复不能绕过 checkpoint 的身份约束。

日频现货报价精度为 3、现金以分记账；分钟按当时规则声明的报价与金额精度记账。参考价和限价必须与本路径规则精度一致。分钟 v7 单独封存执行策略，参与率与正式时间语义绑定。撮合使用执行参与率，TCA 使用其独立声明的参与率上限，两者允许不同。分钟 TCA 到达价采用执行 Bar 原始开盘价，容量采用原始成交量；滑点后成交价及参与率裁剪后的可撮合量保留为执行事实。

## 日频期货与开发验收

日频期货只在提交后的日开盘执行；缺失开盘时间时显式声明 09:00 研究假设，17:00 结算与结算价强平沿用已有合同。比例滑点和 tick 滑点共同作用，按买向上、卖向下的方向舍入，再检查委托限价和价格限制。无 tick 时使用来源报价精度，缺失则取开盘价与命令参考价的较大精度。

日频期货在生产执行处检查命令、历史规则、成交价格与资金预占，再按实际成交处理持仓和结算。开发验收用确定性订单核对费用、盈亏、保证金、强平和恢复后的单次成交。Result 保存正式订单与账本事实，报告不依赖原运行目录。

## 范围

显式订单沿用各资产当前已经准入的市场、账户和数据范围。分钟期货只支持单真实合约；日频期货组合仍按品种独立分配资金。历史交易状态、价格限制和权益仍须满足当时可见的来源要求。入出金收益链、融资、多合约共享期货账户及真实市场扩展按对应能力阶段验收。

## 单笔数量与市价保护

规则区分普通委托与市价委托的买卖数量上限；超限订单被拒绝，项目可显式拆成多个订单，每个子单独立计算最低佣金。可选 `protection_price` 使用Price对象，买入成交不得高于该价，卖出不得低于该价。规则声明 `market_protection_required` 时，缺少保护价即拒单。限价委托仍使用 `limit_price`。

保护价不替代现金预估参考价。资金预估使用下单时可见价格、已声明滑点及费用，撮合再次核对真实成交金额和余额。价格不满足保护约束时DAY余量保留，IOC按原合同结束。显式订单上下文为 `research-explicit-order-execution-v2`，生产执行按相同数量与价格约束处理。
