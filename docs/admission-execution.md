# 准入、选股与交易执行

区分输入检查、选股计算和真实交易。

## 开始前

- 输入：完整研究包、来源、历史规则及预算。
- 输出：准入计划、研究信号、实际交易与账户事实。
- 命令中的尖括号内容是待替换参数。

## 使用顺序

1. 填写数据范围与算法声明。
2. 准入实际来源和历史规则。
3. 执行研究节点生成信号。
4. 让 LEAN 按账户与市场状态处理委托。
5. 从正式 Result 检查交易与终态。

准入冻结可以执行的输入合同。研究节点依据历史可见数据计算候选和信号，LEAN根据当时的账户、订单和市场状态处理交易。准入不运行选股算法，不计算策略收益，也不保证所有订单都能成交。

## 职责与交接

| 环节 | 负责内容 | 正式交接 |
| --- | --- | --- |
| 声明编译 | 数据用途、字段、算法参数、端口及图依赖 | QueryIR与研究DAG |
| 来源准入 | Catalog绑定、实际schema、物理文件、可见范围及资源预算 | 已准入查询、分钟扫描计划与分区引用 |
| 金融输入 | 历史会话、交易规则、公司行动及其可见时点 | 完整minute-scope及金融快照 |
| 研究计算 | 特征、股票池筛选、排名和信号 | 正式Feature或Signal工件 |
| 运行交付 | 按冻结范围读取，并按模拟时钟交付 | 行情、可见规则、信号及账户事件 |
| 交易执行 | 委托、资金、可卖量、T+1、费用、成交及权益到账 | simulation.v2与账户终态 |

准入可以解析规则版本、读取Parquet元数据和估算资源。这些工作只确认输入是否满足合同，不调用项目研究算法。流式消费报告实际行中的错误，例如重复分钟和非法价格。

同次准备和执行交接已经解析的对象。独立运行及恢复从持久计划加载。当前输入、实现或配置变化后重新准入，不用旧计划或旧Result代替新取数。

## 覆盖证券与候选证券

数据覆盖由声明范围、证券身份、真实上市存续和历史来源决定。上市天数门槛、非ST、收益阈值、排名及持仓数量属于研究算法。

候选股票可以每天变化。实际持仓、未完成委托和已登记权益继续保留各自的数据依赖，不随候选删除。性能优化可以按需取报价，但不能只给当日候选交付账户管理所需数据。

执行金融快照按真实覆盖起点生成。选股收益窗口按算法声明计算。扩大物理覆盖不缩短历史窗口，不让新股提前满足原策略的历史条件。新股首发阶段使用当时有效的交易规则，不能套用普通交易日的限制。

## 分钟来源与时间范围

分钟准备使用明确的`--minute-data-root`。物理计划保存所选月文件、实际schema、来源修订和算子声明的扫描预算。scan、resample与LEAN消费同一计划。恢复检查实际来源与计划一致，不用下游默认预算重新生成另一份扫描计划。

同一请求由多个scan节点消费时，物理计划只建立一次。源文件、批次和执行资源预算取各节点允许的最小值，返回行数与能力绑定逐节点检查。预算较宽松的节点沿用共同的最小批次。

QueryIR的`end_at`是半开区间终点，`as_of`是包含端点的可见截止。有效读取终点为两者共同限定的范围。分区引用、会话覆盖和运行日期沿用这一范围。预读下一日可以发生在后台，交给策略的数据仍必须在当前模拟时点可见。

现货执行窗口同时保存请求起止和真实交易会话起止。盘中启动只初始化当前账户，不补发过去的盘前事件。盘中结束记录当时的可见估值和未完成订单，不提前执行收盘撤单、盘后回调或权益登记。

真实收盘时按市场会话执行这些动作。盘中终态与完整收盘净值分别标明估值时点和口径。

## 公司行动与持仓生命周期

公司行动依次消费登记、除权、现金到账、股份到账和可卖时点。只在实际消费除权阶段时要求对应参考价。登记发生在窗口内而除权在窗口外的事件保留登记依赖，不提前读取未来参考价。

当前账户从空仓启动。窗口前已经除权的事件不会产生初始应收权益。窗口前登记、窗口内除权的事件使用明确的零初始登记量。

每个事件按登记当时可见的版本登记一次，后续修订随模拟时钟采用，不反写历史登记。以后若支持导入初始持仓，必须同时提供原持仓和登记权益证据。不能从当前持仓倒推过去登记量。

停牌、退市或退出候选不等于卖出。股票在确认退市生效后，剩余股份按零价值计入研究账户。保留股份数量和归零时点，不产生卖出成交或现金收入。

已经登记的现金权益继续按到账事件处理。普通停牌或缺少行情不触发退市归零。

范围内全部证券已退市时，账户仍观察至请求终点，处理已登记权益并保存实际估值时间。终点观察不新增交易会话，也不调用策略。研究指标纳入终态损失和现金到账，原始日终账户保持原交易日记录。

## 已知限制

退市股份估值归零是本项目的研究假设，记录在Result中。股份的法律状态独立于这项估值假设。模型不模拟退市板块交易或清算收入。未退市证券缺少所需估值来源时，运行报告具体证券、日期及缺失项。停牌历史价不能无条件当作新的公允价值或可成交价。

分钟策略按后续完整分钟价格、成交量与声明滑点撮合。无涨跌幅阶段沿用该模型。历史市价许可、数量、保护价、资金、T+1及已知停牌规则仍在订单消费时执行。

## 设计依据

- LEAN把Universe Selection放在算法执行中。证券退出候选后，已有持仓或未完成订单仍需要数据订阅。见[证券池](https://www.quantconnect.com/docs/v2/writing-algorithms/universes/key-concepts)。
- Qlib由策略按交易步生成交易决定，再交给执行组件。见[组合策略接口](https://qlib.readthedocs.io/en/latest/component/strategy.html)。
- Backtrader按时间交付行情，推进订单和账户，再调用策略，选股或信号不是配置准入。见[Cerebro执行流程](https://www.backtrader.com/docu/cerebro/)。
- 退市后的登记与转让有独立安排，不能把摘牌等同于股份消失。见[关于退市公司进入退市板块挂牌转让的实施办法](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/mainipo/c/c_20250516_10779154.shtml)。
- 非活跃市场资产需要有依据的估值方法。最近成交价不能无条件代表当前公允价值。见[证券投资基金估值业务指导意见](https://www.csrc.gov.cn/csrc/c101896/c1039133/content.shtml)。


## 常用名称

| 名称 | 含义 |
| --- | --- |
| ResearchPackage | 数据、算法、样本、指标和预算的完整声明 |
| Catalog Lock | 已确认的字段、来源和可见性说明 |
| PIT（按时点可见） | 过去某时刻只使用当时已知的信息 |
| bar（周期行情） | 一个日线或分钟区间的行情记录 |
| OHLCV（开高低收量） | 开盘价、最高价、最低价、收盘价和成交量 |
| Feature（特征） | 决策时已知的研究输入 |
| Label（标签） | 用于评价预测的未来目标 |
| bundle（封存包） | 完整代码、依赖或数据声明及其内容身份 |
| checkpoint（检查点） | 通过验收的节点输出和恢复依据 |
| Result（正式结果包） | 正式表、运行摘要及配置、实现和输入引用 |
| minute_scope（分钟范围引用） | 指向同一冻结日历和历史规则的小引用 |
| Supervisor | 监督运行和提交结果的主进程 |
| Worker | 执行节点计算的独立进程 |
